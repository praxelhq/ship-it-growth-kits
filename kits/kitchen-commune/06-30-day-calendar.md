# kitchen commune — 30-day calendar

Daily: 15 minutes for current-session support and aggregate logging. No recording of participant calls. Confirm a real date before inviting a cohort.

| Day | Main job | Time |
| --- | --- | --- |
| 1 | Test two-person email/profile/request/room/control flow; baseline. | 3h |
| 2 | Fix availability expectations and beta/future-price clarity. | 2h |
| 3 | Repair the biggest pairing/video problem and label sample people. | 3h |
| 4 | Record a real willing-pair demo A and hook B. | 2h |
| 5 | Invite ten willing cooks for a confirmed 19:30–20:30 IST window (#1). | 1h |
| 6 | Run first cohort; provide support only, no recording. | 2h |
| 7 | Checkpoint: requests, accepts, attended pairs and no-shows. | 1h |
| 8 | First Reel B / #3 at 19:30 IST. | 1h |
| 9 | Ask three existing group admins for permission. | 30m |
| 10 | Invite ten more cooks for a second confirmed window. | 1h |
| 11 | First LinkedIn #4 at 12:30 IST; send one organizer note #5. | 2h |
| 12 | Share #2 in first two approved groups for the confirmed session. | 1h |
| 13 | Second cohort plus pantry hook C / #3. | 2h |
| 14 | Checkpoint: time-window density and comfort feedback. | 1h |
| 15 | Fix the biggest no-show/request/rejoin issue. | 3h |
| 16 | Share #2 in third approved group, only with a real next window. | 1h |
| 17 | Run invited club cohort if accepted; otherwise help existing cooks return. | 2h |
| 18 | Ask three willing pairs about the session, not private conversation details. | 1h |
| 19 | Record actual control clip D. | 1h |
| 20 | Third Reel D / #3. | 1h |
| 21 | Checkpoint: voluntary second cook and unanswered requests. | 1h |
| 22 | Optional Peerlist maker feedback #6 after current-slot check. | 1h |
| 23 | Fix one real matching/video issue. | 3h |
| 24 | Second LinkedIn #4 about the actual cohort lesson. | 2h |
| 25 | Record another consenting pair only if they want to participate. | 2h |
| 26 | Fourth Reel / #3, no guaranteed-match language. | 1h |
| 27 | One follow-up to willing cooks with an actual next available window. | 1h |
| 28 | Checkpoint: first users versus repeat sessions and completed pairs. | 1h |
| 29 | Concentrate the best working dinner window rather than new cities/time zones. | 2h |
| 30 | Report accounts, available supply, attended pairs, repeats and target gap. | 2h |

If you cannot form a pair in the first window, learn why before adding strangers. Availability and comfort are the product, not a profile-count problem to hide.
