# EATME — Landing-page fixes

The [live wheel](https://www.eatmewheel.in/) was rendered and exercised anonymously on 29 October. Entry→SPIN→meal/alternatives worked without signup in that test. LET'S EAT, ordering, saved favourites and login were not completed. Do not infer those outcomes from a successful spin.

## 1. Make the actual decision the first-screen promise

Current headline: **“What are we eating tonight?”** CTA: **“LET'S SPIN THE WHEEL.”**

Keep the question, add **“Get one meal idea and a short set of alternatives. Pick what fits, then go eat.”** Use **“Choose tonight's meal”** as the entry label if it accurately opens the same wheel. Keep the basic spin accessible before an optional sign-in.

## 2. Explain the three modes before a surprising result

FEEL GOOD/TREAT ME/SURPRISE ME can be expressive but ambiguous. Add one short factual description per mode based on the real selection logic, not imagined nutrition claims. If “personalized” depends on preferences not yet collected, don't use that claim until the input/action is explained.

## 3. Don't let a nutrition number imply precision you haven't established

The observed result displayed calories/protein. Label estimated values clearly, with portions and basis where known. If the values aren't validated, remove precise numbers rather than adding a reassuring badge. Use **“Meal inspiration; check ingredients and your own needs.”** Don't call a wheel medically suitable.

## 4. Give LET'S EAT one unambiguous result

Test the current action and label it for what it actually does: recipe, instructions, a recorded decision or an external search. Don't imply food has been ordered. If a retailer link is used, show that destination and any disclosure before leaving.

## 5. Keep alternatives visible and avoid an endless loop

The result already shows alternatives. Add **“Not this one? Choose another suggestion below.”** Make the primary choice more visible than Spin again. A streak should not be the only sign that the session succeeded.

## 6. Make optional saving and privacy clear

Before favourites/login explain what is stored and whether an account is needed. Don't ask for location, health conditions or contacts merely to spin. Test a fresh browser and an expired session; don't claim “no signup ever” because the first spin worked.

## 7. Check phone usability and shared previews

The inspected metadata disables user scaling; enable readable zoom rather than blocking it. Title: **“EATME — choose a meal with one spin.”** Description: **“Meal ideas and alternatives for the dinner-decision moment.”** Test keyboard/focus, motion preferences, result readability and a slow network. Keep meal choice usable if decorative emoji or images fail.
