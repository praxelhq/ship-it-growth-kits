# PortalFlow — Phone-demo scripts

Use a fictional design studio and an owned sample image. Record your screen and voice; mask account details and access links. A recipient must be a consenting internal tester. Local preview and shared delivery must remain visibly different.

## A. The exact version — 65 seconds

0–3 s: two owned sample versions. **“Which one is waiting for approval?”**

3–17 s: actual supported owner workspace, labelled with its verified mode. “Start with one deliverable and the version you mean.”

17–32 s: actual change/review state, if implemented. “The next action needs a clear owner and file.” Leave one real supported interaction continuous.

32–47 s: second-device client view only after verification. “This is the actual recipient view.” If only a preview exists, say “This is a local preview; nothing was sent” and show that disclosure.

47–55 s: owner return and actual decision state if verified. “Check that the result survives the return.” Do not fake a saved approval.

55–65 s: current mode/offer and URL. “Know what saves and shares before client work. portalflow.store.”

## B. Preview hook — 20 seconds, Short

0–3 s: demo disclosure. **“Preview is not sent.”**

3–12 s: actual button and mode label. “A local client view can explain the design. It does not prove an invitation arrived.”

12–20 s: actual entry and URL. “Test the recipient path before using private work.”

## C. Decision hook — 25 seconds, LinkedIn

0–3 s: fictional approval beside a version label. **“Approved what?”**

3–15 s: show the exact owned file and next-action state. “The decision belongs to a version, not the whole project forever.”

15–25 s: source/state check and URL. “A useful portal makes that boundary clear.” No legal signature or client-result claim.

Capture actual sign-in headings, conflicting demo wording, verified save mode, real supported review actions and second-device outcome only when tested. If authentication is the only observed capability, record the boundary walkthrough and repair before promoting a successful client-work demo. Label wait cuts and fictional assets.
