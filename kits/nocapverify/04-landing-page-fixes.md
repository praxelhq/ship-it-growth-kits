# Nocapverify — Landing-page fixes

Homepage, methodology, pricing and campaign entry read 29 October 2026. No report/API response, private account or payment was tested. Public statements are not independent verification.

## 1. Reconcile facts, estimates and scores

**Current:** HowWeVerify says every number comes directly from APIs, no estimates/no trust scores; homepage advertises pricing estimates, ROI projections and a 0–100 Trust Score.

**Write:** **“Observed platform fields · derived calculations · estimates · unavailable information.”** Put the source/date/method beside each result. Remove absolute no-estimation/no-score wording where it conflicts. Don't promote a heuristic as proof of bought followers or a model output as raw API data.

## 2. Reconcile free versus Pro access

**Current:** homepageFAQ says everything free; pricing lists ₹0 Free/₹999 Pro; campaign entry asks for a free account.

**Write the actual entitlement after testing it:** **“Create an account, then see which features your current plan includes and the full charge before purchase.”** Make homepage, pricing and logged-in gate agree. Free account doesn't necessarily mean free campaign planning. Until resolved, don't send a priced planner pitch.

## 3. Make the first job inspectable

**Current headline:** “Discover Creators with AI.” CTA: “Plan Your Campaign.”

**Write:** **“Inspect the evidence behind your creator shortlist.”** Supporting line: **“Check sources and uncertainty before a campaign decision.”** Test signup→permitted candidate→actual report→source review before acquisition. If the core path fails, repair it; don't use a static sample as proof of live reporting.

## 4. Label the sample and remove unsupported traction

**Current:** sample report with a public-channel description, date/ID and partial fields; large generic loss/fraud figures and counters.

**Write:** **“Illustrative report unless independently confirmed; not a customer outcome.”** Show real aggregate usage only from actual records and a defined period. Remove unsupported ₹loss/follower-inflation claims rather than repeating them as market facts. A uniqueID isn't evidence the sample's data is authentic.

## 5. Explain API availability and privacy

**Current:** broad real-time YouTube/Instagram claims can imply every desired metric is available.

**Write:** **“Available fields depend on actual source access. Missing data remains missing.”** Verify each supported field, permission and timestamp; don't guess hidden analytics or claim an independent API audit. Explain actual storage/provider handling before private campaign data. No public fraud label from a ratio.

## 6. Keep source labels readable on phones

**Current:** fit, trust, price and ROI features compete with the underlying evidence.

**Write the output order:** **“Source first. Method second. Decision remains yours.”** Test 360 px, large text, keyboard, unavailable-report states and source links. Preview title: **“NoCap Verify — creator evidence to review.”** No clipping/load defect was measured; check rather than invent one.
