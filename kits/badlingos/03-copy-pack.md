## Reuse without spamming

For the second post, change the problem example and the first two lines. Show a different real step, not a new unsupported outcome. Never invent a user quote or a result to make a post sound lived-in. If you publish a learning from five testers, say five and keep the test notes. Invite a friend to try the activity only if they asked for the link; do not ask them to like, vote or comment to boost the post.

Do not use the cohort profile as a substitute for a working product link. Recover and verify the actual URL before any product invitation. Answer replies yourself for the first hour, then check twice that day. If a question needs a private account or personal material, move to an agreed private support route instead of asking for screenshots in public.
