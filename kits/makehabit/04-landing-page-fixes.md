# MakeHabit — Landing page fixes

Public page and rendered controls checked 29 October 2026. Authentication, guest persistence and checkout were not tested. The initial article extraction omitted controls; a body extraction showed real entry buttons and price, so do not call the CTA missing.

## 1. Explain the small action before the broad promise

Current headline: “Turn everyday routines into lasting habits.” Current controls: “Continue with Google,” “Try without signing in,” “Plans(₹199 Lifetime).”

Replacement:

> **After the thing you already do, remember one small next action.**
>
> Choose a familiar cue, attach an ordinary action and keep an honest record. Start with one pair.
>
> **Try one stack without signing in**
>
> Choose Google sign-in when you want the account features. Check what each mode saves.

Only promise cross-device sync after a real account test. Keep the tactile demo as the signature element rather than adding more generic feature cards.

## 2. Separate public demo from a saved personal stack

The page invites “Click checkmark to test” and shows a seven-day streak/100% consistency example. Label it clearly:

> **Interactive example, not your record.** Try the feedback here; create your own pair to start tracking.

A demo click must not increment the user's actual history or be counted as activation. Test this rather than assuming it from the animation.

## 3. State guest storage at entry

“Try without signing in” is a useful lower-friction path. Explain the actual device/browser limitation and what happens when data is cleared. Do not imply cloud backup for a guest.

Copy after verifying implementation:

> Guest records stay in this browser. Clearing browser data can remove them. Use an account only if you want its supported saved/sync features.

If the actual storage differs, write that truth. Test migration/sign-in before promising a guest record transfers automatically.

## 4. Replace broad neuroscience wording with the observable workflow

The page says “Build habits without willpower fatigue” and refers to neural pathways. This review did not validate efficacy claims for this app.

Replacement:

> **Make the next action easier to remember.** Pair it with a routine you already notice. Start small, log honestly and adjust if the cue does not fit your day.

Link the actual [habit-stacking explanation](https://jamesclear.com/habit-stacking) as background without implying its author endorses the product. Do not promise effortless or lifelong change.

## 5. Explain the ₹199 lifetime plan before payment

The rendered navigation advertises ₹199 lifetime. Publish the actual included features, free/guest limits, device/account scope, final tax total and refund path before checkout. Do not let the nav label carry the whole purchase contract.

Suggested summary structure:

> **Lifetime plan —₹199 advertised.** See the included entitlement and final payable total before buying. This is separate from trying the guest interaction.

Test a purchase only under owner-approved test conditions; this inspection did not buy or activate anything.

## 6. Test one setup and one later day

Observe three willing adults create one pair, log an actual action, leave and return. Test Google cancellation, guest refresh, storage clearing warnings, timezone/day changes and a missed cue. If essential saving or return fails, pause promotion and repair it.

Use ordinary actions in examples, not unverified prescriptions about water, sun, sleep or treatment. A public demo example is not individualized advice.

## 7. Mobile and private-data checks

No visual audit was performed. Test 360 px, large text, keyboard access, reduced motion and sign-in return. Keep the first action and mode limitation legible. Mask habit names and account details in analytics.

Suggested title: “MakeHabit — one cue, one small next action.” Description: “Try an anchor/action pair and log what actually happens. Guest and account modes.” Check the actual preview privately; do not expose a private habit by default.
