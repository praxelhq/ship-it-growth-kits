# Uhgfix — Landing page fixes

Public home and full-body pricing pages checked 29 October 2026. A generated response, task start and paid entitlement were not tested. Do not say checkout is broken: the page explicitly labels payments coming soon.

## 1. Reconcile Pro trial, price and unavailable payment

The home says seven days Pro free. [Pricing](https://ughhfix.in/pricing) displays ₹99/month or ₹799/year, says Pro stays on this phone/browser and warns against clearing browser data, then labels payments coming soon.

Until purchase is available, use:

> **Pro payments are not open yet.** Try the current task flow. The advertised plans are ₹99/month or ₹799/year; final checkout terms will be shown before payment becomes available.

Explain the real seven-day trial start/end and browser persistence, after testing them. Do not make a “buy now” promotion for a coming-soon payment path or promise account recovery the product does not have.

## 2. Put the usable first step beside the joke

Current headline: “Ughh… kya avoid kar raha hai?” Current CTA: “Ughh… theek kar de.” Keep the voice, add the limited job:

> **Bas ek chhota start.**
>
> Ordinary kaam batao. Apna tone chuno. Ek usable pehla step lo—poora kaam ya life fix karne ka promise nahi.
>
> **Pehla step dikha**

English counterpart:

> Tell me the ordinary task. Choose the tone. Get one small starting step.

## 3. Make tone consent and quiet controls obvious

The page offers several personas, “Chup ho ja” and reduced animation. Keep a neutral/quiet path visible before generation and make the chosen tone easy to change. A character should not start insulting or playing audio without a deliberate choice.

Copy:

> Choose a style you want. Change it or keep things quiet anytime.

Test actual sound/animation defaults rather than assuming the visible mute label proves every path behaves properly.

## 4. Show a real input and usable output

The home lists ordinary examples. Add one actual response from your own non-sensitive task, clearly labeled as a demonstration, with a visible later “I started” result only if it occurred.

Structure:

> What I was avoiding → the small step → what I actually started.

Do not fake task completion or call a first-step suggestion a full plan. If the result is only a joke, fix the response before sending more traffic.

## 5. Test the no-account return and data boundary

Observe three adults enter an ordinary task, choose language/tone, request a response, mute it and return after refresh. Test network failure, empty input, long input and browser storage clearing. Confirm whether previous tasks and Pro state persist and how the user can delete them.

The page says typed text is masked in Clarity; verify masking in actual recordings. Do not put task bodies into analytics events. A browser-bound entitlement needs a visible limitation before a trial or payment, not only a small note afterwards.

## 6. Separate entertainment from activation

Add a low-pressure next action only if implemented:

> Was this small enough to start? Started / I need a smaller step / Not useful.

This is feedback, not proof the whole task is complete. Avoid public streak rankings, guilt escalations or forced sharing to unlock a useful answer.

## 7. Check phone/language/share experience

No visual audit was performed. Test 360 px, large text, Hindi rendering, keyboard access, reduced motion and audio mute. The price/trial/device note must be readable before any upgrade.

Suggested title: “Ughfix — bas ek chhota start.” Description: “One ordinary task, one chosen tone, one small next step.” Never place private task text into a public preview by default.
