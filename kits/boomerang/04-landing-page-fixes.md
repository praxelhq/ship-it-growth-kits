# Boomerang — Landing page fixes

Home/privacy read 29 October 2026. Actual authentication, extension install, capture, AI and sync were not tested. The page is live; the launch boundary is the disclosed development state and unverified release path.

## 1. Make beta/data limits visible before capture

Current headline: “Good ideas deserve a way back.” The [privacy disclosure](https://www.boomerangit.me/privacy.html) describes a development build, configured providers and complete cloud export/deletion not yet available in-app, with manual requests handled by support.

First verify the supported release and support process. At the entry use:

> **Free beta for non-sensitive reading and research.** Review where this mode saves content and which connected providers process it. Keep originals separately and check the current export/deletion options.

Do not claim production certification, an encrypted local vault or complete self-service export. If a promised launch control is still absent, keep promotion at pilot scope until resolved.

## 2. Sharpen the passage-return job

Current controls: “Start your library” and “Install Chrome extension.” Supporting copy:

> **Save the passage you will need again.**
>
> Keep its original source and why it matters. Return to your project with the context intact.
>
> **Save one public source**

The exact passage and original link should lead; optional summaries/topics support the job. Preserve the current calm reading direction.

## 3. Verify the actual install destination

The rendered controls advertise a Chrome extension, but a live store/install completion was not established here. Test the exact current route in a clean Chrome profile: download/store entry, permissions, sign-in, capture, return and uninstall. Do not promote a store listing that does not exist or imply a development package has passed store review.

If sideloaded beta, call it that plainly and offer a web-only test if supported. Do not make unfamiliar users guess which ZIP, account or build they need.

## 4. Explain local versus connected libraries

The privacy page says local web/extension libraries can be separate, account sync requires configured services, and existing local saves upload only through explicit import. Show the actual mode at save:

> Saved in this mode. Check whether this is local-only or connected to your account before expecting it on another device.

Use the precise supported message after testing. Explain clearing storage, uninstalling and explicit import. Never imply archive equals deletion.

## 5. Keep quotation and summary visibly different

The home correctly says selected passages keep original words and summaries are optional. Preserve labels:

> **Selected passage:** original words from the linked source.
>
> **AI summary:** optional interpretation; check important claims in the original.

Use a permitted short excerpt or your own article in the demo. Label illustrative sample articles as examples, not user libraries or factual research.

## 6. Explain provider processing at the decision

The disclosure describes OpenRouter and possible River processing in configured modes. Do not replace it with “nothing leaves your device.” Before enabling a connected AI action, state what source context is sent and link the actual provider disclosure. Use non-sensitive material until processing is appropriate for the user.

Test a failed capture, unavailable source, scanned document, network loss and later retrieval. Do not promise full text from every URL or a paywall workaround.

## 7. Keep payment/test state and analytics honest

The disclosure says beta is free and approved test checkout does not activate a paid plan. Remove any production-buy implication. Never ask a tester for real payment details in a test flow.

Public analytics are opt-in and masked per disclosure; preserve that. Do not send saved passages as custom events. No visual audit was performed: check 360 px, large text, keyboard access and the return from sign-in.

Suggested title: “Boomerang—your useful passage, with a way back.” Description: “Save permitted sources and context in a free beta. Current storage/provider limits explained.” Preview privately without exposing a library.
