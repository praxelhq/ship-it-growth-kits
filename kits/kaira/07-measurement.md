# Kaira — Measurement

## Baseline

On 29 October 2026, [the public course profile](https://shipped.money/p/kaira) displayed **no eligible readings** for authored-source shipping days, Clarity sessions, Search clicks, net revenue or PostHog page views. Baseline is **not known**, not zero traffic, zero work or zero users. Obtain legitimate owner analytics/account totals before using a number in a launch post. Don't add Clarity and PostHog together if both become connected.

Keep the **1,000 B2C account target**, with activation and voluntary return alongside. A signup-page visit, countdown click or extra habit record isn't a new account.

## Milestones and privacy

Measure aggregate `signup_completed`, `first_task_saved`, `dated_task_saved`, `focus_reason_viewed` where genuinely instrumented, `task_completed`, `reminder_shown`, `return_day_1`, `return_day_7`, `export_completed` and `delete_completed` only according to actual consent/policy. A shown reminder isn't proof the user acted on it. Ask opt-in feedback about whether the ranking helped without recording task text.

The policy discloses strict-masked Clarity, anonymous account identifier and plan. Audit that existing setup; don't add duplicates. No task titles, freeform logs, health/habit values, email, exact personal timetable or exported contents in events/replays/public screenshots. Events should use category, success/error and coarse source, not private content. Data-deletion claims require actual owner verification, not just a button label.

Private aggregate ledger: date, source, eligible visits, verified new accounts, first dated tasks, completion, next-day/seven-day return among eligible cohorts, date/ranking/reminder errors, opt-outs, hours, spend. Source tags: `warm-planning`, `owned-focus`, `organizer-planning`, `peerlist`. Remove known overlap between workshop attendees and warm invitations. State any anonymous attribution limitations instead of fingerprinting.

## Weekly checkpoints and diagnoses

**Day 7:** Can five voluntary testers create an account and save a correctly dated task, and explain the ranking's reason? Five is a learning goal. If signup works but tasks don't, inspect first-use setup. If dates are wrong, pause invitations until parsing/timezone is fixed. A headline rewrite can't repair a wrong deadline.

**Day 14:** Look for a real task attempted/completed and voluntary next-day return. If accounts accumulate but first tasks don't, simplify onboarding. If tasks exist but reasons confuse, explain urgency rules. A user deliberately choosing another task isn't a product failure.

**Day 21:** Compare invitation/post/accepted-session cohorts on dated tasks and return use, not raw clicks. If reminders “fail,” split app closed, permission issue, timezone issue and actual missed open-app delivery. Don't blame users for expecting a background notification the copy implied.

**Day 28:** Review real repeat use and whether habits/logs help the first audience. If the main objection is another account/setup burden, improve the first-three-task loop rather than invent a larger feature bundle. Check export/deletion/privacy feedback before seeking a bigger partner.

**Day 30:** Report verified new accounts, first dated-task activation, actual task completion, eligible next-day/seven-day return, source contribution after deduplication, errors, hours and costs. Remaining gap is 1,000 minus legitimate new accounts, never minus task records. The 02 assumptions produce only roughly 4–19 activations without a session or 8–26 with one before overlap; no unaccepted editorial/launch traffic is in the base. Avoid claims that a month of app activity proves improved grades, mental health or total productivity.
