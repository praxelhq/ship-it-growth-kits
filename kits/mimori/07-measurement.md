## Baseline

On 29 October 2026, [the public profile](https://shipped.money/p/mimori) showed **2 authored-source active days** for 21–27 October UTC (21/22 October), last sync 28 October 21:18 UTC, and **0 settled Search clicks** for 17–23 October PT. Clarity sessions, net revenue and PostHog had **no eligible readings**, not zero. Accounts, references, private saving and retention are **not known**. Source activity isn't user traction; don't add views and sessions if later connected.

Keep the **1,000 B2C account target**, with first private reference saved/retrieved/connected alongside. A no-account sample visitor is separate. Six bundled photographs, board cards and metadata exports aren't people or accounts.

## Milestones and data boundaries

Track aggregate sample entry, reference selected/captured, annotation saved, literal search attempted/matched, board reference connected, human interpretation saved, reset/reload, signup completed and first **private** reference saved. Private retrieval on a later eligible day is the deeper outcome. Distinguish sample metadata export from account/original-photo export; don't invent a capability or event from a button label.

No photograph, EXIF location, image embedding, title/note/tag words, private storage URL, project interpretation, email or portfolio link in growth events/replays. Use count/category/success/error/source only, with actual policy/consent. Guest sample says local in-memory; don't silently upload temporary images for “analytics.” Check existing trackers and masking before adding anything. If app events aren't legitimately available, use aggregate volunteered observations and say total unknown.

Private aggregate ledger: date, source visits, sample loop completed, verified new accounts, first private saves, retrieval success, project connections, voluntary later use, failures/opt-outs, hours/spend. Source tags `warm-reference`, `owned-process`, `organizer-reference`, `peerlist`. Deduplicate known overlap; avoid fingerprinting people or counting a sample visitor again as an unrelated new account.

## Weekly checkpoints and diagnoses

**Day 7:** Can five voluntary testers find a sample by a word they wrote and explain why an absent word won't match? Five is a learning gate, not a forecast. If users expect visual AI search, fix copy/demo; don't call their expectation a success because they clicked signup. Independently verify real account saving.

**Day 14:** Can the reference become a human interpretation on a board without confusion? If captures are high but retrieval low, inspect annotation wording and no-result feedback. A reload losing guest changes is intended but must be understood; accidental loss from unclear copy is a real trust problem.

**Day 21:** Review private-save→later-retrieval among eligible real accounts. If people only play with samples, report sample engagement, not retained private libraries. If storage/auth checks fail, zero durable-account activation is the honest forecast until repaired. Don't import separate owner-local AI research metrics to fill a product evidence gap.

**Day 28:** Inspect second project use, image-rights handling, data boundaries and actual mobile-device results if tested. Browser-responsive screenshots aren't iPhone performance evidence. No claim that agent-authored relevance judgments validate creative usefulness for students.

**Day 30:** Report sample visitors/loop completions, verified accounts, first private references, literal retrieval, source-linked interpretation, eligible return use, source totals after deduplication, hours/spend and 1,000-account gap. The 02 base assumptions are only roughly 3–14 private-save activations without a session, 4–18 with one before overlap, and zero if account readiness fails. Unaccepted launches/editorial/directory visits remain zero until real. No fabricated testimonials or automatic-creative-output claim.
