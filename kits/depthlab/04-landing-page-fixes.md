# Depthlab — Landing-page fixes

Checked 29 October 2026: home, library, one philosophy brief/discussion, review queue and login. No answer, microphone access, email or payment was submitted.

1. **Keep the specific real headline.** “Know it well enough to explain it” is the useful promise to test. Add **“Start with one sourced question. Read, explain in your own words and apply it to a new case.”** Primary **“Try one brief”** should open an actual public lesson; secondary **“Explore the 36-brief library.”** Don't send every first-time learner to a large category grid.

2. **State time honestly by brief.** The library labels most briefs 12 minutes, but some fiction topics show 20 or 90 minutes. Do not advertise the whole product as a five-minute daily app. Keep each actual duration visible and say **“Choose a brief that fits the time you have.”** Test whether labels match the real task including practice, not reading alone.

3. **Separate available learning from planned billing.** Current ₹499/month section says payments aren't open. Make **“Planned membership: ₹499/month. Payments are not open. Join launch updates only if you want them.”** explicit. Keep public brief access usable; a waitlist confirmation is not a subscribed learning account.

4. **Show what feedback actually does.** Use a clearly labelled original test answer, feedback and a new application attempt. Add **“Feedback is guidance, not a validated grade or proof of mastery.”** The checked brief says no specialist peer review; retain that limitation instead of implying academic endorsement.

5. **Make speaking optional and recording controls clear.** Discussion currently offers speaking or typing and explains mute/pause/end differences. Keep **“Type if you prefer. Microphone starts only when you choose it.”** Explain what is sent, saved and deleted before voice use. Do not promise that muting alone stops capture; the page distinguishes it from pausing.

6. **Explain account value before the email link.** `/reviews` asks people to sign in for the queue, and login sends an email link. Use **“Sign in to keep your review queue. Public briefs remain readable.”** only if that matches implementation. Test link delivery, return routing and expiration with an authorized account; this kit has not done so.

7. **Preview and phone checks.** Title **“Depth Lab — explain and apply one idea”**; description **“Sourced briefs, teach-back attempts and later review. Planned membership billing is not open.”** Test source links, long brief text, typed-answer input, recording states and visible errors on a phone. A source badge isn't proof the source supports every sentence; spot-check actual citations before promoting.
