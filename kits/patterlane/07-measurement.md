# Patterlane — Measurement

## Baseline and access reality

On 29 October 2026, [the public profile](https://shipped.money/p/patterlane) showed **no eligible readings** for source active days, Clarity, Search clicks, net revenue or PostHog. Actual traffic, invitations accepted, installed users and retention are **not known**, not zero. Don't infer zero work from missing source readings or add sessions and views together later.

Keep the **1,000 B2C account/install target**, explicitly separate from temporary/sample evaluation. Current free access is limited to first 100 accepted invitations and paid activation is closed. The target cannot be promised from the current offer; report access/readiness gap rather than calling sample visits admitted users.

## Milestones

Sample measures: visit, conversation opened, to-do created, sample reply reviewed, language switched, voluntary return. Sample creates no real mail delivery or AI evidence. Native milestones only after gates: admitted identity/invitation, compatible first launch, owned-test-provider connection/sync, meaningful conversation/task/review, confirmed controlled send and voluntary later use. A Google identity login is not mailbox permission or first synced message.

The sample privacy page says no application analytics SDK/ad tracker. **Don't silently install growth tracking that contradicts it.** Use aggregate voluntary observation/feedback or update actual policy/consent before instrumentation. Likewise do not infer native telemetry from local activity logs; those may contain addresses/task titles and aren't a public dataset or tamper-proof ledger.

No mail bodies/addresses, contact notes, task titles, credentials/tokens, invitation URLs, identity IDs, plaintext exports or unsanitized logs in growth analytics/public demos. Operational access records stay separate from marketing. No copying provider mailbox credentials into a classroom worksheet or spreadsheet. Local encrypted storage doesn't protect a compromised active OS session.

## Private aggregate ledger

Date, source, sample visitors/completed exercise where actually observed, invitations offered/accepted legitimately, native gates passed, known test first launches, safe controlled connection/sync/send outcomes, failures/opt-outs, hours/spend. Source tags can be simple link-level aggregates only where consistent with current policy. Deduplicate known workshop/warm overlap without fingerprinting or collecting people's inboxes.

**Day 7:** Can five voluntary evaluators understand conversation→task/review and know no real email/AI is running? Five is a learning gate. If people believe the sample sent mail or granted founder access, fix 04 first. Record native gate status separately; automated local fixtures aren't live-provider validation.

**Day 14:** Identify sample flow friction and real-mail expectations. Does the UI-language switch preserve original messages? If native startup/signing/support/configuration remain open, don't invite real credentials. Report zero observed native activations, with total user count still unknown if not supplied.

**Day 21:** Look for voluntary sample return and specific preference over existing inbox layout. Native adoption only counts when admitted and actually launched/tested. No participant owes an install or purchase to make the metrics look better. Payments closed means no forecast paid subscribers.

**Day 28:** Audit remaining release gates, first-100 availability, support readiness and privacy/export risks. Don't promote a “local” architecture as proof no server data or network exists. Provider access grants require separate revocation; disconnect/export/backup boundaries stay explicit.

**Day 30:** Report sample evaluation separately from genuine admitted accounts/installs, native meaningful use, controlled sends, source overlap, failures, hours/spend and remaining gap to 1,000. 02 base only estimates 5–20 sample evaluators without an event or 7–25 with one before overlap, **zero native conversions until gates pass**. Unaccepted launches/community/editor/directory routes remain zero in the base. No claims of proven live-mail reliability, all-user privacy certification or mass-launch readiness.
