# Spikewatch — Measurement

**Target: 10 real business customers in 30 days.** Each team business must satisfy [all four tests](../../TARGET-POLICY.md): genuine operation; own actual authorized usage onboarded; independent operational use within seven days; privately known owner name/phone. Store identifiers outside the public repo. Count teams, not API organizations, alerts, users or provider keys.

Activation: an authorized real team reviews a known synthetic case, then successfully uses the chosen supported path on its own actual usage with a verified operational responder. Report checker-only evaluations, active self-hosted teams and hosted-live teams separately. A one-off browser sample, reservation form or price calculator does not qualify. No hosted payment is assumed until live and actually charged.

No private usage or account data was accessed; active monitor counts and hosted capacity are unknown.

| Baseline | Source / boundary |
| --- | --- |
| Real businesses / latest independent operational use | Owner-confirmed actual setup/status plus private permitted register. |
| Chosen path and current availability | Actual checker/self-host/hosted state, not reservation intention. |
| Own-data checks / responder review | Minimal status evidence with consent, no usage exports or secrets in growth logs. |
| Synthetic detection/delivery failures | Controlled fake-data tests, no manufactured paid incident. |
| Alerts investigated / valid traffic | Consented aggregate reason categories, not confidential bill details. |
| Price/payment and course metric | Actual billing if live, [profile](https://shipped.money/p/spikewatch), timestamp/period. |

Check existing [Clarity](https://clarity.microsoft.com/) before adding a duplicate. Mask/exclude usage input, keys, webhook URLs, Slack/channel identities, reservation contacts and account/payment screens. Do not assume client-side processing makes replay safe. Minimal events: samplechecked, approvedpathconfigured, actualmonitorverified, responderreviewed, laterindependentoperationaluse. No token counts, prompts, credentials or detailed bill data belong in marketing events.

| Checkpoint | Decision |
| --- | --- |
| Day 7 | Eight approaches scheduled. If owners expect instant hosted service or guaranteed savings, fix 04 and the opener. |
| Day 14 | 20 approaches. Separate own-data operational setups from checker samples/reservations. Verify actual permission and ownership. |
| Day 21 | 28 approaches. Inspect independent running use and responder understanding; a false alarm is not proof of waste. |
| Day 28 | 40 approaches. Audit all four tests and path labels, no waitlist/customer mixing. |
| Day 30 | Actual qualifying teams against ten, activation/path, independent use, actual payments, hours and target gap. |

Base guesses: 40 × 50% × 70% × 70% = 9.8 businesses; at 25% conversation, 4.9. Three posts/two intros are upside only. Replace assumptions after eight approaches and again after 20. Hosted capacity may be zero; report self-host adoption explicitly rather than pretending managed sales. If no own-data path is actually used, the honest customer count is zero.

Estimated spend is not a provider invoice, a threshold crossing is not waste and an alert does not stop requests. A hypothetical calculator saving is not revenue or verified cost avoidance. Publish only permitted actual setup/use observations; no invented incidents, prevented losses, security certification or testimonials.
