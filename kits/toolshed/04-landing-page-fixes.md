# Toolshed — Landing-page fixes

Actual H1 **“You keep finding good tools. Then you lose them.”**, banner **“Not launched yet — building in the open.”**, **Browse the directory** → `/discover`, **Start your shed — free** → `/register`. Free unlimited saved tools/no card. Public pages read; no signup/fetch/save/export/deletion tested. Ranked trust/retrieval recommendations.

## 1. Fix the private-note/recording mismatch before sensitive use

The homepage mentions an exception; the [policy](https://tool-shed.app/privacy) makes it concrete: notes/email/library screens can appear in Clarity, with no current consent/refusal and recordings not deleted by account deletion. Don't erase that disclosure with a generic “strict masking” claim. Owner should exclude/mask private content and sensitive routes, implement actual consent choices where appropriate and verify behavior before a confidential-note pitch.

Until a verified correction, replace the note headline with:

> **Non-sensitive notes only for now.** Other users can't open your library, but usage recordings can show notes and email to people with Clarity access. Account deletion doesn't delete those recordings. Read the current policy before saving anything private.

This isn't legal compliance advice; it is the real stated processing boundary. No data collection needed to test it—use synthetic notes and owned accounts only.

## 2. Give a concrete retrieval exercise

Keep the H1, add:

> Save one public tool for a real job. Check its fetched details, put it in the use cases you recognize, then find it later when that job returns.

CTA **Browse public tools first**. Secondary account CTA includes actual privacy/access terms. A directory visit isn't a saved-library success. Show a public example with one tool in two categories, not a fabricated AI recommendation engine.

## 3. Scope automatic metadata and URL safety

Suggested input help:

> Paste a canonical public product URL—not a private dashboard, invitation, token or client link. We fetch basic details; you check name, description, logo and current offer before saving.

Owner tests failed fetch, redirects, duplicate URLs and editable fields with public links. Don't claim automatic price validation or safe arbitrary intranet fetching without verification. Fix actual fetch error messages before promoting “paste, not a form.”

## 4. Explain what 84 tools and “pick” mean

The public directory says 84 tools, with picks. Suggested label:

> Curated directory count, not customers or endorsements. “Pick” means our editorial selection under the stated criteria. Check the tool's own price, access and terms before using it.

Publish actual selection/sponsorship criteria and distinguish sponsored placement if present. Don't imply every tool is free, every logo is a partnership or every lawyer/consultant prompt is professional advice. Link to canonical vendor sources rather than copying stale prices.

## 5. Keep paid-kit claims separate from the free library

Navigation/policy mentions kits, all-access and advertising, but this audit verified no amounts. Publish actual current item price, contents, access/delivery/refund terms at the relevant checkout. Don't invent “free kits” from a free-library headline or forecast kit revenue as account acquisition.

Suggested free card:

> Personal library: free, no saved-tool limit, no card. Optional paid items have separate terms shown before purchase.

Use only if actual signup behavior matches. Owner tests access/entitlements using controlled data before paid outreach.

## 6. Make export/delete consequences explicit

The policy describes JSON export and immediate account/library deletion, but session recordings remain separate. Suggested account help:

> Export your library before deleting it. Deletion removes the account/library and isn't reversible; it doesn't automatically remove prior usage recordings held in Clarity. Read current retention details.

Verify real export/deletion and secret-token route exclusions on owned accounts. Signing out doesn't clear tracking cookies per policy; don't call it a total analytics opt-out. Useful retrieval and informed storage choice matter more than rapidly collecting notes.
