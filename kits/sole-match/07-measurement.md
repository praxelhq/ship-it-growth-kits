# sole match — Measurement

**Target: 1,000 consumer signups.** Because account entry is unverified during recovery, provisionally use **distinct first working preference/search sessions** under the no-account equivalent. Before the recovered month begins, check whether an account is required. If so, set new real accounts as the headline and report sessions separately; don't switch definitions midway or add both together. Activation alongside: **a user inspects a genuinely useful shortlist and its reasons**. A retailer visit, purchase and comfort outcome are separate and unproven.

## Day 0 after recovery

The [course profile](https://shipped.money/p/sole-match) has the footwear description but no eligible connected-source readings in the checked period. Missing data isn't zero adoption. Record actual current accounts if present, usable sessions, result success/failure, inspected candidates, return use and rank/timestamp. Source-line count isn't product usage. The submitted domain's certificate access problem is a recovery finding, not proof no code exists.

Check existing [Clarity](https://clarity.microsoft.com/) and actual consent/privacy before adding another tag. Mask preference text, email and any personal field. Proposed content-free events, only if supported: `preference_session_started`, `shortlist_requested`, `shortlist_succeeded`, `shortlist_failed`, `reason_opened`, `candidate_rejected`, `seller_link_opened`, `return_session`. Do not collect health/foot images, addresses or private retailer checkout data to measure discovery.

## Scheduled forecast

Assumptions rather than observed rates:

- 30 invitations × 50% try × 60% working start = **nine starts**.
- Six posts × 200–800 impressions × 2% visits × 40% start ≈ **10–38 starts**.
- One accepted session: 15 invited × 60% attend × 60% start ≈ **five**, otherwise zero.
- One optional launch: 0–100 visits × 40% start = **0–40**.

Total **19–92 before overlap**, below 1,000. If the recovered app requires accounts, these start assumptions do not automatically become account conversions; measure that extra step and lower the forecast. At an assumed 40% visitor-to-session rate, 1,000 starts needs 2,500 qualified visitors; the calendar doesn't establish that reach.
