# Pehlu — Measurement

## Your target and activation

**1,000 consumer signups in thirty days** remains the [assigned policy](../../TARGET-POLICY.md). A signup is one new non-test account, not a Telegram notification or an answer. **Activation is a first saved reflection the person can find again.** Report those two counts beside one another. Telegram connection, scheduled delivery and weekly-perspective use are separate later steps.

## Day 0

| Baseline | Source | What to record |
| --- | --- | --- |
| Existing accounts and first saved answers | Product store/events | Actual values; public-page research did not establish them. |
| Sessions and referrers | Existing landing analytics | Period, source and tests excluded. |
| Telegram opted-in/delivery success | Already-disclosed operational metadata | Counts only, no chat identifiers in public reporting. |
| Current cohort reading/position | https://shipped.money/p/pehlu | Timestamp and period; missing reading is unknown, not zero. |

The privacy summary already permits optional Clarity on the public landing page only. Check that configuration rather than adding a duplicate tag. Keep replay off all private/reflection/auth/billing routes and never send answers, insight text, names or chat identifiers to analytics.

## Events you need

Account created; first answer saved; saved answer reopened; Telegram connected/paused; scheduled delivery succeeded/failed; weekly perspective opened/corrected; voluntary later-day return. Use minimal completion metadata and only events consistent with the product's disclosures. A long or emotional answer is not a better growth metric.

## Checkpoints

| Day | Compare | Decision |
| --- | --- | --- |
| 7 | The scheduled five invitations, one clip and one post: delivered visits → accounts → first saved answers. Observe five attempts. | If nobody starts, fix invitation/fit. If accounts stall, fix first-answer/control clarity. |
| 14 | Three clips, two posts and ten invitations cumulatively; actual account and activation rates. | Replace02 assumptions; do not add unheld event reach. |
| 21 | Accepted-session attendance, private later starts, returners and weekly-perspective control use. | Fix delivery or interpretation confusion before more acquisition. |
| 28 | Distinct new accounts, first reflections, voluntary returns and privacy complaints. | Repeat the source producing actual use; never relax the counting rule. |
| 30 | Signups, activations, returners, hours and gap to 1,000. | State the actual result and the next verified distribution route. |

Do not total overlapping cohort snapshots or count the same Telegram user again every day. The small-network forecast is below target; do not hide that by reporting message deliveries as signups. Quote a user only with permission, and never include a private reflection in a public results note.
