# Relay — Positioning

**Live:** https://relaycontext.app/ · **Category:** Developer tool · **Profile:** https://shipped.money/p/relay

**This is an early Mac build, not a universal tool switcher.** The live H 1 is “Switch AI tools without starting over.” The current page says it reads Claude Code and Codex session files and opens Claude Code with a handoff. Opening Codex, Cursor, ChatGPT, Lovable and Windows are coming next. Do not advertise those as working destinations.

The “Get started free” CTA points to `/app?start=1`; the site also offers a Mac ZIP. The first two handoffs are free on one computer, no card. **$25/month is planned; paid plans are not open.** Neither account creation nor installation nor generation was performed for this audit.

The page explicitly says the Mac build lacks Apple Developer ID signing/notarization and says that comes before public launch. Honor that. Fix distribution and publish clear support/operator details before a broad install campaign. Don't make security-warning bypass commands your marketing instructions.

## Your first user

A solo builder on a Mac who has been working in Codex, wants to continue one small non-confidential project in Claude Code, and is about to spend twenty minutes explaining past decisions again. They can check a handoff and understand that a path in a brief doesn't grant filesystem access.

Start with five experienced builders, not an entire bootcamp. Ask them to use a toy project, inspect the preview and identify what is missing. Your early advantage is a reviewed brief with explicit gaps, not magical continuity across every app.

## The pitch

> Continue a Mac coding project in Claude Code with a handoff you review first: the work so far, decisions made and the next step.

Short version: **Review the context. Carry the project forward.**

The wedge is resuming one concrete next action after a handoff. Show a small repo, a recorded decision, a missing/uncommitted change explicitly identified and the destination checking its access. If the next assistant confidently acts on an obsolete assumption, generation succeeded but the product failed.

## Real alternatives

A local Markdown handoff and manual copy/paste cost₹0 in extra handoff software. A builder can write the goal, current state, decisions, files and next action themselves; show why Relay's capture/preview reduces omission, not why people supposedly can't write notes.

[ChatGPT Free](https://chatgpt.com/pricing/) offers general summarization, but a user still must choose safe context and verify it. Don't imply a cloud summary is local-only or that another model has access to the repo because the brief mentions a path. Relay must earn installation friction with a better verified transition, not merely a longer summary.

## The honest weakness

The homepage says sessions are encrypted locally and only approved text is uploaded for brief generation. It also says pattern-based redaction can miss secrets. That makes the preview part of the core task. “Zero cloud uploads,” “perfect redaction” and “the whole story” without gaps would be misleading.

The [support page](https://relaycontext.app/support), updated 16 October, describes a broader manual-import/web workflow, temporary cloud results and active-subscription billing language. Reconcile it with the current landing page's narrower Mac build and unopened paid plans. Publish one accurate supported-flow matrix before outreach.

Keep the **1,000-consumer-signup target**, counted as new installs with first successful reviewed handoff alongside. A gated early build with five testers will not clear it immediately. Be honest about the launch gate and earn a reliable small transition first.
