# Fan Wars India — Measurement

**Assigned B2C target: 1,000 signups in 30 days, paused until verified relaunch.** Current withdrawal-notice visits, refunds and support requests are not new-product signups.

Private payment/account records weren't accessed. The site's promise to refund is not proof every payment has been returned.

| Recovery baseline | Actual source |
| --- | --- |
| Notice issued/updated time and stated processing window | Official page plus owner's records |
| Completed/pending refunds and support cases | Authorized private provider/support records, never public payer data |
| Current purchase/signup routes closed | Fresh public browser test |
| Replacement product/offer availability | Actual live page and core-action test, not a future sentence |
| Current course metric/rank/time | [Profile](https://shipped.money/p/fan-wars-india) |

If analytics such as [Clarity](https://clarity.microsoft.com/) already exists, don't add a duplicate. Mask support/payment/identity fields and do not replay transaction details. Current site traffic measures communication reach, not acquisition success.

## Relaunch measurement, only when ready

Define a signup from the actual product: a confirmed account, install or first meaningful no-account session under the policy. Define its first useful action from a demonstrated live flow. This kit cannot responsibly invent an activation event for an unknown replacement.

Ten voluntary prototype tests come first. At a purely hypothetical 25% visitor-to-signup, 1,000 would require 4,000 qualified visits; there is no evidence of that channel or rate today. Replace the arithmetic with measured facts before a growth forecast.

| Checkpoint | What you report |
| --- | --- |
| Day 7 | Actual recovery status, dated notice and support availability |
| Day 14 | Replacement exists/doesn't exist; specific readiness blockers |
| Day 21 | Voluntary tested users and real completed actions, if any |
| Day 30 | Recovery state and relaunch decision, with zero invented acquisition |

Keep old payments, refunds and any new revenue separate. Don't count a refunded payer as a new user or a future offer as a sale. Course 24-hour readings overlap and cannot become cumulative signups. Honest recovery is a valid result while the product remains withdrawn.
