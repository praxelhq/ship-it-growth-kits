# Fan Wars India — 30-day calendar

**Recovery comes before the acquisition clock.** The sequence below is a hold/relaunch workflow, not a promise to reach 1,000 while withdrawn. Start the board's 30 acquisition days only after the replacement is live and verified.

| Day | Main job | Time |
| --- | --- | --- |
| 1 | Verify actual withdrawal/refund status privately; record public notice date. | 2h |
| 2 | Put a dated, accurate status and usable private support route on the site. | 2h |
| 3 | Check acknowledgements/delivery; no new purchase or signup. | 2h |
| 4 | Review owned social/link previews for obsolete promises. | 1h |
| 5 | Publish status #3 only through genuine owned channels if needed. | 1h |
| 6 | Resolve current support work; keep private records out of the repository. | 2h |
| 7 | Recovery checkpoint: actual completed/pending status, no invented totals. | 1h |
| 8 | Decide whether any replacement exists; write only its verified action. | 2h |
| 9 | Define intended audience/offer from the real product, not the old name. | 2h |
| 10 | Test the replacement's core action if it exists; otherwise remain on hold. | 3h |
| 11 | Review privacy/support/eligibility and actual pricing. | 2h |
| 12 | Fix the first blocking conversion/fulfilment issue. | 3h |
| 13 | Record current-state video A, not a fictional promo. | 1h |
| 14 | Readiness checkpoint: real replacement or honest continued pause? | 1h |
| 15 | If ready, invite five willing prototype testers using #4. | 1h |
| 16 | Observe actual first action, no payment/referral requirement for feedback. | 2h |
| 17 | Fix the largest issue; keep recovery separate. | 3h |
| 18 | If ready, invite five more voluntary testers. | 1h |
| 19 | Compare actual comprehension and completion. | 1h |
| 20 | Write product-specific positioning only from the real replacement. | 2h |
| 21 | Checkpoint: can a stranger use it without misunderstanding the old status? | 1h |
| 22 | Verify every public claim, link and current offer again. | 2h |
| 23 | Record a real replacement demo only if all gates pass. | 2h |
| 24 | Consider one permitted free community/maker-feedback route; zero assumed reach. | 1h |
| 25 | Reply to genuine feedback; no hype-based comeback count. | 1h |
| 26 | Fix a real issue rather than adding paid distribution. | 2h |
| 27 | Recheck recovery/support obligations and current notice. | 1h |
| 28 | Checkpoint: old obligations and new-product evidence reported separately. | 1h |
| 29 | Choose whether to start a separate verified acquisition month or stay paused. | 1h |
| 30 | Handoff actual recovery state, real prototype evidence and remaining gates. | 2h |

No fixed relaunch date is invented. If the gates don't pass, the correct Day-30 result is a clear hold, not fabricated users.
