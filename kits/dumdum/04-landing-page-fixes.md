# dumdum — Landing-page fixes

The live H1 is **“A small creature that lives on your desktop.”** **Download for Windows** currently resolves to `#download`, **Buy Pro** to `#buy` in rendered links. Free $0 with account, Pro “Soon · one-time.” This audit did not execute an installer, payment, reminder or cloud/calendar integration. Fix recommendations below require owner verification.

## 1. Make the download verifiable before increasing reach

The public link inventory didn't reveal a concrete installer destination. Verify the actual button behavior in a normal fresh browser, published version, file availability and publisher/signing information. Don't label the site dead: the marketing page renders normally.

Proposed button block:

> **Download dumdum for Windows**
> Windows 10/11, 64-bit · about 300 MB · version [actual released version]. Free account needed for notes. Mac not available yet. View release notes and publisher details before installing.

Fill the version only from the actual release. Replace routine “Run anyway” instructions with transparent support guidance: stop and verify the release if Windows warns; don't normalize bypassing protection as onboarding. A downloaded file isn't yet a successful install.

## 2. Separate available free value from an unpriced Pro offer

Replace a purchasable-sounding Pro card while no amount is visible:

> **Pro — early access, price not yet published here.** One payment, no subscription. Check actual availability and the full price before buying. Free notes/reminders remain available with a free account.

If sales are live, publish the numeric amount, currency/tax, supported features and license delivery at the button before taking traffic there. Test actual entitlement on a controlled owner account; don't claim the public Dodo mention proves payment delivery.

## 3. Put the account and network boundaries beside the first task

Suggested short explanation:

> Your notes sync to your account. Document conversion runs locally with bundled LibreOffice. Optional calendar connections send your reminders as events; they do not read your calendar. AI Mode has separate processing terms—read them before entering anything sensitive.

Do not replace the missing AI policy with an invented “all local” promise. Show where note/account deletion, export, disconnected behavior and permissions are documented. Audit replay masking before any public note demo.

## 4. Show a real reminder rather than a cute notification mockup

Suggested first-run instruction:

> Create a harmless test note due in a few minutes. Confirm Windows notifications are allowed, and decide whether dumdum should start with Windows. Calendar export can be connected later or skipped.

Owner tests app open/closed, restart, timezone and permission denial. Explain actual constraints discovered. The site's fictional reminder is not proof a user's notification arrived. Don't collect notification contents in analytics.

## 5. Make file safety inspectable

Keep “It only takes a copy” and add a visible synthetic example:

> Original: `sample.txt` stays in its folder. Returned copy: `sample (1).txt` if that name already exists on Desktop. One file at a time. Conversion results are new files; check them before using them.

Test duplicates, locked files, cancellation and the stated 100 MB warning without destructive operations on private files. Avoid “perfect PDF→Word” fidelity promises; document the actual supported formats and known limitations.

## 6. Let the pet be easy to stop

Show how to pause reactions, disable startup and quit/uninstall, using actual controls. Suggested caption:

> Keep the reactions you like. Turn others off in Settings; startup is optional.

Measure successful first note/reminder and voluntary return, not maximum screen time. The narrow first-use story is more credible than six unverified Pro promises at once.
