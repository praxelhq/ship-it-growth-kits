# askpragzy — Landing-page fixes

Homepage, `/start` and `/analyze` read 29 October 2026. No actual private interview script or transcript was submitted. A reachable form isn't proof the analysis is correct.

## 1. Make the result a review, not validation

**Current `/start` headline:** “Review your interview questions.” The homepage says “Most ideas don't fail. They get validated wrong.”

**Write:** **“Challenge the questions before your next customer interview.”** Supporting line: **“Spot leading and hypothetical wording. Review the critique; real interviews still determine what you learn.”** Avoid implying an AI output can certify demand or explain why most ideas fail.

## 2. Put today's supported input first

**Current:** Interview is available; Survey, file upload and start-from-scratch are marked coming soon.

**Write:** **“Available now: paste up to 30 interview questions.”** Keep unavailable options visually secondary and clearly labelled. Don't send a button labelled Upload to an unsupported flow. Test idea context → pasted questions → review → usable corrected script with synthetic data before outreach.

## 3. Show one inspectable question correction

**Current action:** “Review my questions” asks the visitor to trust the result before seeing the workflow.

**Write beside a labelled example:** **“Original question → concern → alternative to review.”** Use a synthetic question and explain why the alternative seeks observed behaviour. Don't display a green “validated” score or a claimed improvement in willingness to pay.

## 4. Make answer-review formatting obvious

**Current `/analyze`:** one customer, up to 30 questions/answers, with Q:/A: prefixes.

**Write:** **“One conversation at a time. Label each question Q: and answer A:.”** Include a short synthetic example and a clear error if nothing parses. “0 exchanges found” should explain the required format, not look like a completed negative research result.

## 5. Explain seven-day retention before paste

**Current:** results saved for seven days then deleted; only entered content used for review is stated.

**Write:** **“Paste only content you're authorized to process. Remove private customer details. Read the current processing and retention terms.”** Verify actual provider/storage/deletion behaviour before making a stronger promise. Don't equate no signup with no data handling.

## 6. Make the phone review and preview clear

**Current:** several context fields precede the script.

**Write button helper:** **“Your script stays editable after the review.”** Use only if the actual flow supports it. Test 360px, keyboard, long questions, errors and copy/export behaviour. Suggested preview: **“Ask Pragzy — review the questions before the interview.”** No specific mobile or load failure was measured; check it rather than inventing one.
