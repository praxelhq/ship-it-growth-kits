# Fintellix — Landing-page fixes

Root, `/login`, `/signup` and public route metadata were read 29 October 2026. No account was created and private controls weren't tested. Login-required isn't a down-site verdict.

## 1. Explain actual work before asking for a firm account

**Current:** login says “Welcome back.” Signup says “Your practice, in order” and “Create your firm's private workspace.”

**Write:** **“See one supported practice workflow before creating your firm.”** Add a clearly labelled synthetic walkthrough of actual released functions, not a speculative feature collage. If the private app is not ready for independent work, state a design-partner stage. A generic account gate doesn't give the owner enough evidence to decide.

## 2. Make the signup action's scope clear

**Current CTA:** “Create firm account,” with firm name, responsible name, work email and password.

**Write beside it:** **“Review current plan and data terms before adding client records.”** Test controlled firm creation → actual supported task → saved result → independent return. If the job cannot complete, repair it before live-data outreach. Publish the real price/trial limits; none was established publicly, so don't invent free access.

## 3. Substantiate “private” with an inspectable scope

**Current:** “private workspace” is the public promise.

**Write:** **“Who can access records, how access changes and what export/deletion support exists.”** Verify actual controls with synthetic records and authorized accounts before stating them as facts. Don't claim audited security, local-only storage or perfect firm isolation from the presence of authentication.

## 4. Separate current features from route titles

**Current:** public client metadata names task/checklist routes, while the accessible page doesn't demonstrate them.

**Write:** **“Available now”** only beside actual tested released features, and **“Planned”** elsewhere. A route description isn't proof a workflow works. Do not imply automated reminders, filing or statutory guidance without actual capability and review.

## 5. Keep professional responsibility explicit

**Current:** the firm-oriented presentation can invite assumptions about compliance work.

**Write:** **“Your professional reviews requirements, dates and records before acting.”** Avoid using sample client/year text as legal advice or a claim of automatic correctness. Demonstrate record review with synthetic data, not real PANs or bank files.

## 6. Verify the phone/account handoff

**Current:** a login/signup entry is the main public experience.

**Write the walkthrough around one actual task**, with a visible saved/failed state. Test 360px, enlarged text, keyboard, password/account recovery and the actual shared preview. Suggested title: **“Fintellix — a scoped workspace for your practice.”** No clipping/load defect was measured; check instead of alleging one.
