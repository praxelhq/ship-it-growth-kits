# ReturnRescue — Measurement

**Target: 10 real business customers in 30 days.** Each brand must satisfy [all four policy tests](../../TARGET-POLICY.md): genuine operation; own actual permitted return data onboarded; independent use within the last seven days; privately known owner name/phone. Keep identifiers outside this public repo. Free/manual users can qualify if actual supported use meets all tests; paid-inactive users do not.

Activation: the operator physically checks an actual item and reviews one recovery comparison using its real condition/cost assumptions. Report this beside customer totals. Suggested route, chosen route, action completed and cash actually recovered are separate states. Ten returns in one brand are not ten businesses.

No private account data was accessed; baseline totals and actual recoveries are unknown.

| Baseline | Source / boundary |
| --- | --- |
| Genuine brands / latest independent use | Workspace records plus private permitted owner register, excluding tests. |
| Own returns physically reviewed | Actual permitted item data/status; no buyer identity in growth logs. |
| Grade corrections and cost changes | Aggregate reason categories and owner-reviewed comparison. |
| Recommended/chosen/completed routes | Separate actual status; a recommendation is not fulfillment. |
| Expected versus actual recovery | Real net proceeds and relevant costs when known, not model estimates as revenue. |
| Trial/paid quotas, expiry, refunds/course reading | Actual billing/counters and [profile](https://shipped.money/p/returnrescue), timestamp/period. |

Check existing [Clarity](https://clarity.microsoft.com/) before adding a duplicate. Exclude customer/order labels, private photos, addresses, financial contracts, account/payment fields and item-access links from replay. Minimal events: ownreturnadded, physicalreviewconfirmed, assumptionsreviewed, routerecommended, routeselected, actioncompleted, actualrecoveryrecorded, laterindependentuse only where supported. Do not send raw photos or private order data into marketing analytics.

| Checkpoint | Decision |
| --- | --- |
| Day 7 | Eight approaches scheduled. If a photo suggestion hides uncertainty or costs cannot be checked, repair before more actual decisions. |
| Day 14 | 20 approaches. Compare own items and reviewed decisions; confirm trial expiry/next access. |
| Day 21 | 28 approaches. Inspect independent use after trial and actual chosen/completed routes; do not assume paid AI access. |
| Day 28 | 40 approaches. Audit all four business tests, distinct brands rather than return items. |
| Day 30 | Actual qualifying brands against ten, activation, recent use, expected/actual recovery, payments/refunds, hours and gap. |

Base guesses: 40 × 50% × 70% × 70% = 9.8 businesses; at 25% conversation, 4.9. Three posts/two intros are upside only. Replace rates after eight approaches and again after 20. Trial limits and real recovery cycles may reduce recent use; report useful one-off comparisons separately instead of asking everyone to log in before measurement.

A photo grade is not condition certification, an editable fee is not verified tax treatment, and a partner listing is not an available buyer. A return's original retail price is not recovered revenue. Report only actual permitted observations, with dates, costs and limitations; never invent recovery percentages, saved margin or testimonials.
