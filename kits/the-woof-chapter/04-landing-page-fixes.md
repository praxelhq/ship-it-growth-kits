# The Woof Chapter — Landing-page fixes

Read against [the live page](https://thewoofchapter.in/) on 29 October 2026. The current headline is **“A little universe. A very big personality.”**; the action is **“Try the comic book studio”**. A small free preview allowance applies, with no sign-up needed for available guest features. No verified live paid offer exists in the checked terms: checkout is test mode and planned payment is per comic, not a subscription. This audit records visible copy and inspected routes; it does not claim a signed-in workflow, payment or device test was completed.

Your visitor is an adult pet owner checking what the current prototype can actually deliver. Give that person one obvious next action and a real example of the result. Keep the product's own visual character; fix the task hierarchy before adding decorative sections.

## Fix 1 — Put the prototype boundary before upload

**Current:** The hero promises a pet universe; terms say automatic photo artwork is still in development.

**Write this instead:**

> Try the pet-story prototype: edit a draft and choose the illustrated character manually. Automatic photo artwork is still being built.

**Verify:** Place it beside the first photo/story action, not only in terms.

## Fix 2 — Prevent paid-delivery confusion

**Current:** The billing route exists, but current terms say checkout is test mode.

**Write this instead:**

> Test checkout only. It does not buy a finished comic or real credits; do not enter real payment-card details.

**Verify:** Disable or clearly separate test purchase actions from public conversion tracking.

## Fix 3 — Keep coming-soon experiences separate

**Current:** Films and talking avatars are marked coming soon.

**Write this instead:**

> Available now: the story/comic prototype. Films and talking avatars are future work.

**Verify:** No launch clip should imply those experiences can be used today.

## Fix 4 — Explain optional AI photo processing

**Current:** Privacy says optional colour matching sends the selected photo to Gemini’s unpaid API quota.

**Write this instead:**

> Optional AI colour matching sends this photo to the provider. Use a pet-only image without people or sensitive background information.

**Verify:** Keep the choice explicit; do not claim photos never leave the browser when the user requests AI.

## Fix 5 — State guest-save limits

**Current:** Terms say guest sessions belong to this browser and email confirmation does not automatically upload a local draft.

**Write this instead:**

> Guest drafts belong to this browser. Use the actual save or download action; confirming an email alone does not save the draft.

**Verify:** Test refresh, device change and account save with a harmless draft.

## Fix 6 — Make public sharing a real choice

**Current:** Public share links publish a separate comic copy and preview.

**Write this instead:**

> Create a public link only if you want others to read and reshare this copy. Your original photo is not the shared preview.

**Verify:** Verify the current share/remove route before promising withdrawal; cached/downloaded copies may remain.

## Release check before the first invitation

Open the public URL in a clean phone browser on mobile data. Have someone who has not seen it explain what will happen after the main action, then try it. Check permission denial, a slow connection, back navigation and the narrow-screen keyboard. Log the exact route and device if it fails; a research fetch failing is not a dead site. Do not send traffic into a route you have reproduced as broken.

Make one change at a time after the baseline. Keep a dated screenshot and the old wording so a better conversion number can be tied to the change. Do not call a copy change an improvement until people complete the intended activity more often.
