# Sherpa — 30-day calendar, listing recovery gated

One to three hours daily. The acquisition clock begins when the correct intended app route and first useful action work. If a gate fails, continue recovery; never claim the scheduled invitations happened.

| Day | Action |
| --- | --- |
| 1 | Record `07` baseline and owner-verified package/release facts, #1. |
| 2 | Establish intended device, region and access-track availability. |
| 3 | Resolve actual listing cause or verify current official replacement link. |
| 4 | Test the route from a fresh eligible device context. |
| 5 | Record real use case, headline, price, account and permission needs. |
| 6 | Test authorized install/first launch/useful action with synthetic data. |
| 7 | W1 gate: correct identity, official route and usable first action. |
| 8 | Correct owner-controlled course link/description using #3. |
| 9 | Invite three consenting adult supported-device testers #4. |
| 10 | Observe actual access/install/launch/action attempts without coaching. |
| 11 | Fix the biggest first-use or permission error. |
| 12 | Record private walkthrough A only for verified paths. |
| 13 | Establish actual buyer and note provisional roster classification. |
| 14 | W2 gate: actual signup/install and useful-action definitions. |
| 15 | Request five prospective-user interviews #6 about the actual job. |
| 16 | Verify the real alternative and its official price/access. |
| 17 | Verify two destinations those users actually named. |
| 18 | Read current rules/request organizer permission before a pitch. |
| 19 | Write the true app benefit from observed first-use evidence. |
| 20 | Record actual product demo and factual listing preview. |
| 21 | W3 gate: job, first use, supported audience and checked channels. |
| 22 | Run one five-person permitted acquisition test; log exact volume. |
| 23 | Support access/device errors privately without collecting credentials. |
| 24 | Check real useful completions, not just installed status. |
| 25 | Ask consenting testers #7 about voluntary return. |
| 26 | Repeat one five-person test only if activation/permission justify it. |
| 27 | Audit actual app analytics; exclude internal/test installs. |
| 28 | W4 review: listing recovery, funnel and target gap. |
| 29 | Document current devices/access/price/permissions and unresolved blockers. |
| 30 | Deliver honest recovery report and actual acquisition start date. |
