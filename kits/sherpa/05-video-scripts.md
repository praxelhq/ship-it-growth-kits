# Sherpa — Video scripts, recovery evidence

Use your own supported device and screen recording. No unverified APK, credentials, private data or invented app interface. Product-specific demo shots begin only after recovery.

**A. Link to useful action, 55 seconds; private review first.** Hook: “An app link needs to lead to a usable app.” 0–10s show the dated supplied-listing result. 10–20s show the verified current official listing only after recovery, with real availability/price. 20–40s show authorized first launch and an uncut actual first action, hiding account information. 40–55s show real success or blocker. Say, “This is what a new eligible user can finish today.” If still blocked, stop at the observed gap; do not fill the video with imagined features.

**B. Not Found means investigate, 20 seconds.** Hook: “This link failed; that isn't the whole app's history.” Show the supplied package and current error without guessing cause. Say, “I check owner release records and the intended access conditions before claiming a delisting or a fix.” Use as an honest status clip only if still current.

**C. Same name, different app, 20 seconds.** Hook: “A familiar name isn't a verified replacement.” Show your owner-confirmed package identity after recovery, without credentials. Say, “The link, owner and screens need to match this project. I won't substitute another Sherpa from search.” No unrelated app footage.

**D. Installation isn't the finish, 20 seconds.** Hook: “A first launch still has to do something useful.” Show the actual implemented first action after verification. Say, “I'll report the first useful completion beside installs or accounts. A loading screen doesn't count.” If unresolved, keep this as a private test script rather than producing fake success.
