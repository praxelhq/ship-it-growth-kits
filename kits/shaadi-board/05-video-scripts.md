# Shaadi Board — Video scripts

No real household boards, guest lists, names, contacts, travel details or wedding photos. Use a fictional event with generic Helper A/Helper B roles. Native app/board footage requires recovered legitimate access; proposed paper exercises must be labelled proposed, not live product proof.

## A. Working Ops demonstration — 55 seconds, after recovery

**0–7s:** Fictional run sheet. “Who owns the next job?” Overlay *Fictional rehearsal, not a real wedding*.

**7–19s:** Open actual authorized sample Ops board. “This is the recovered workspace.” If still unavailable, stop here and use transparent repair update B instead; don't animate success.

**19–31s:** Show one actually implemented task/owner/time control. “One job, one clear current owner.” Do not create a fake assignment/notification UI in editing.

**31–43s:** Follow the actual supported handover/update behavior. “What does the next helper need?” If the app lacks a handover field, show its real supported note/workflow and state the limit.

**43–50s:** Show safe access boundary and actual error/backup guidance if implemented. “Keep a fallback run sheet for a live event.” No guarantee all private boards are secure.

**50–55s:** Actual verified evaluation/access terms and safe link. No invented free price, signup or customer count.

## B. Hook — 24 seconds, Day 10, usable during repair

**0–6s:** Actual Ops error cropped without private data. “A page loading isn't the same as a board working.”

**6–16s:** Public router, then actual error. “The router works; Ops needs recovery. I'm not asking families to rely on this screen.”

**16–24s:** Fictional run-sheet concept labelled *Proposed first test*. “Fix delivery, then test one handover.” No false app/demo CTA; update the clip if repaired.

## C. Hook — 25 seconds, Day 16

**0–6s:** Generic fictional chat message “Someone handle arrival.” “Someone isn't an owner.”

**6–17s:** Actual verified board task or clearly labelled paper exercise: Helper A, invented time, next step. “Make the current owner and next handover clear.”

**17–25s:** “A fictional rehearsal before a live wedding.” Safe evaluation link if available. No real family chat screenshot.

## D. Hook — 25 seconds, Day 24

**0–6s:** Generic invite link hidden by a privacy card. “A wedding board isn't public product proof.”

**6–17s:** Fictional sample roles and actual access explanation. “Show sample tasks, not a household's guest list.” Don't imply untested role controls work.

**17–25s:** “Test access and fallback before the event day.” Actual safe link/terms only. No real household endorsement or inferred guest-count traction.

Six posts can use these four assets plus text repair/workflow lessons. Correct state matters more than cinematic wedding imagery; don't spend budget filming a celebration to disguise missing first-use access.
