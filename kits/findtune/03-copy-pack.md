**Use only after recovery and a real successful intended-input test.** Current public deployment has no mounted app. These drafts assume only a remembered-word candidate-search loop; change the claim if the recovered build supports something narrower. No unfilled event details, invented song results or copyrighted lyric excerpts are needed.

## 1. Warm listener test

> Would you try a small song-finding flow on an example you're allowed to use? I build FindTune and want to know whether remembered words lead to a candidate you can inspect. It won't recognize everything, and a candidate still needs checking. Please don't send private recordings or full lyrics. A no-match result is useful feedback too: https://www.findtune.shop/.

Once after seven days: “Closing the loop on the search test. If you don't need it now, no problem; I won't keep nudging. If you tried, was the problem entering the words, finding a candidate or checking the match?”

## 2. Owned-feed demonstration

> Remembering a few words and knowing the title are different problems.
>
> I'm testing FindTune's short remembered-word search flow: enter what you recall, inspect possible matches and check the one you recognize. It isn't a promise to identify every song or a claim that humming works.
>
> This clip uses material I have permission to show, and the result is real. Try the current working scope at https://www.findtune.shop/. Tell me about the input/result step that didn't work, without posting private audio or full lyrics.

Use only with an actual recorded result, not a staged success.

## 3. Useful reply

> I would separate “music is playing now,” “I remember words” and “I remember only a melody.” Those need different inputs, and a tool should say which it actually supports. Check the candidate rather than treating the first result as certain.

No product link unless asked. Don't claim competitors cannot handle an input without current evidence.
