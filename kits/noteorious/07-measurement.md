# Noteorious — Measurement

**Target: 1,000 signups in 30 days**, defined for the native app as **valid new installs/first launches**, with **people completing a checked consented note** beside it. [Target policy](../../TARGET-POLICY.md).

Count purchases, downloads, first launches, model-ready installs and first usable notes separately. Exclude tests, bots, reinstalls, repeated launches and license activations on a second Mac from the new-person headline where the same buyer is known. Activation requires a real consented recording/import and checked result. Retention is independent later-day use, not an automatic app-open ping.

## Day 0 baseline

[Public profile](https://shipped.money/p/noteorious), checked 29 October, showed latest saved Clarity 0 sessions/24 h for 28 October, sync 16:33 UTC. One shipping-active day and $0 net revenue for 21–27 October; zero settled search clicks for 17–23 October. No rank was visible. These are period readings, not lifetime totals.

Private purchases/install/note totals were not supplied. Record actual values before promotion. The privacy page already describes anonymous install/activation/daily-open counts; do not claim zero telemetry or add meeting-content analytics. Keep web Clarity separate from native usage and mask receipt/license data.

Useful aggregate stages: `purchase_succeeded`, `download_completed`, `first_launch`, `models_ready`, `permission_granted`, `test_recording_completed`, `notes_ready`, `result_checked`, `later_day_use`, `refund_recorded`. Only measure stages actually supported; do not treat a model-ready UI as a successful note. Never send transcript/audio/license content as growth events.

## Forecast and decisions

The actual plan schedules twenty peer invitations, two demos, eight clips and one listing.02 models **8–81 valid first launches before overlap**, not enough evidence for 1,000. At assumed 10% qualified-visitor-to-install, you need 10,000 qualified desktop visits. Replace the rate with actual data. No paid receipt alone closes the activation gap.

| Day | Install milestone | Paired decision |
| --- | --- | --- |
| 7 | 50 | Three real install/model/result tests pass; fix setup before reach. |
| 14 | 150 | Checked-note users, not receipts/downloads only. |
| 21 | 500 | Real compatible-Mac routes and voluntary introductions; reforecast gap if expansion is absent. |
| 28 | 850 | Independent later use, result errors and refunds. |
| 30 | 1,000 | Installs/first launches, activated note users, returns and net paid outcomes together. Report a miss plainly. |

Milestones are decisions, not predictions. Weekly rows: qualified desktop visits, purchases, downloads, model-ready first launches, checked-note users, later users, errors, refunds and hours. Show numerators/denominators.

Paid users without launch point to delivery/installation. Launch without models ready points to setup. Model-ready without notes points to permissions/recording. Results without use point to wrong owners, dates or language handling. A local-processing promise does not prove note accuracy, and no-bot does not justify hidden recording. Repair the actual failed step before more exposure.
