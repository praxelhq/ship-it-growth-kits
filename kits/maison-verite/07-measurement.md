# Maison Vérité — Measurement

**B2C target: 1,000 new consumer accounts in 30 days.** Report **completed, correctly understood first red-flag reports** alongside. Activation requires receiving a report and understanding that it isn't an authenticity certificate. An upload, a preset click or an AI confidence number alone doesn't establish value.

Check existing [Clarity](https://clarity.microsoft.com/) before adding another script. Mask uploads, account fields and report content; never send photos, serial codes, seller names or private notes into analytics. Minimal events may include `sample_opened`, `account_created`, `check_started`, `photo_rejected`, `check_completed`, `check_failed`, `scope_acknowledged`, `second_check`, `paid_upgrade` only where actually measurable and accurate.

## Arithmetic

At an assumed 20% qualified-visitor-to-account rate, 1,000 accounts needs 5,000 visits. If half complete and understand a report, that is 500 activations. Those are hypotheses, not evidence of accuracy or demand. Twenty warm invitations, eight posts, one conditional session and directory discovery plausibly form a **10–30 first-report experiment**, with overlap removed. They don't establish 5,000 visits.

Don't close the gap with an unverified accuracy percentage or viral fake-detection claim. Track whether a user correctly treats the output as a prompt for further checking. A shared report that someone mistakes for a certificate is an interpretation failure, not a successful referral.

## Weekly decisions

| Day | Decision |
| --- | --- |
| 7 | Three fresh readers must explain the limitation and identify a sensible next question. Misinterpretation as certification: fix before wider distribution. |
| 14 | Fewer than five of ten willing testers complete a sample check: inspect upload/auth/error friction. Many unsupported confident results: narrow scope and correct the product. |
| 21 | Do users return for a real next photo/question, without pressure? Check shared-result wording and privacy. Don't claim purchase safety from a repeat check. |
| 30 | Report accounts, completed reports, correct interpretation, repeat use, upgrades/refunds, hours and target gap. Keep accuracy evaluation separate and only publish valid evidence. |

These are experiment decisions, not authentication standards. Never use an AI report as the sole basis for accusing a seller or guaranteeing a transaction. Remove misleading public examples and correct the actual output path if confidence exceeds evidence.
