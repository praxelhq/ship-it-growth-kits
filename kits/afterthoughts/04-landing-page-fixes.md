# Afterthoughts — Landing-page fixes

Checked 29 October 2026 from the public homepage and email-code login. “Try it” is a real JavaScript demo control; “Start tonight” goes to/login. No microphone, email code, account recording, transcription or recall question was submitted. The /privacy route required login in this check.

## 1. Explain local demo versus account processing

**Current:** the demo says “It stays in this browser — nothing is sent anywhere,” while Start tonight creates an account for private recordings. The page also says recordings aren't used to train.

Put a public, implemented data-flow explanation before capture: **“This public demo stays in this browser. Account recording, transcription and storage work as described below.”** Then state actual providers, retention, deletion/export and what is uploaded. Don't copy a local-demo assurance onto an account upload. Make privacy information readable without signing in before a visitor decides to record.

## 2. Connect the headline to retrieval

**Current:** “Say the day out loud.”

Keep it and add:

> **Find it later by a word you remember.**
>
> Keep a non-sensitive first note, read the transcription and return to the source recording. Descriptive patterns aren't judgments about you.

The focal proof should be one actual capture-to-search path, not a longer emotional headline or a fabricated life story.

## 3. Make first-use choices specific

**Current:** “Try it” and “Start tonight.”

Use **“Inspect the browser demo”** and **“Create my diary account”**, with accurate access/price/recording limits before entry. No paid amount was publicly visible, so don't add a free-forever claim by default. Test the email-code path, resend/error states and return to the same page on a fresh phone.

## 4. Keep examples and pattern limits visible

The page already labels sample nights invented and says patterns aren't verdicts. Keep those labels in cards, exports and short clips. If a tag says how an entry sounded, use **“Suggested description from this entry; review it”**, not a claim to infer a person's mental state. Don't make a repeated name into a relationship conclusion.

## 5. Prove source-grounded recall

**Current:** “Ask your past” says answers cite the nights they draw on.

Show one actual question and the exact source entry it returns, using invented content. Add **“If the diary doesn't contain the answer, it should say so.”** Test a deliberately unanswerable question rather than stage perfect memory. Don't count an eloquent unsupported answer as a successful recall.

## 6. Demonstrate control over a first recording

Test stop, playback, correction if available, delete/export and failed upload on a synthetic note. Explain what survives reload and which controls actually exist; don't claim undeployed editing. Preserve a clear cancel state and never continue capture after the user thinks it stopped. No private diary text in analytics or support screenshots.

## 7. Phone and preview

Proposed title: **“Afterthoughts — say it tonight, find it later.”** Description: **“A voice diary with source-linked retrieval. Inspect the demo and recording/privacy terms before keeping a first note.”** Test actual cards, microphone permissions and playback on phones; no measured load/clipping defect was established. Keep the privacy distinction and recording state readable with the keyboard visible.
