# Cutroom — Landing-page fixes

Read the actual [workspace](https://cutroom.space/) and rendered Plans & exports on 29 October 2026. Current headline: **“less admin. more action.”** CTAs: **“New project”**, **“Your projects”**. Free ₹0 has three total exports; Creator ₹1,799/month and Unlimited ₹12,000/month show **“Checkout not connected”**. No paid purchase, shared review or export was exercised.

## 1. Define local versus shared state

Current empty state describes a private browser workspace; the wider page promises people, projects and reviews.

Replacement: **“Start a sample project here. Before using client work, check how projects are saved and shared with your editor.”**

Replace that with exact verified persistence/access behavior when known. A login link does not establish cloud sync. Show what survives refresh, sign-in and another device before claiming shared access.

## 2. Give the first job a clear shape

Current “New project” competes with several service buttons and navigation areas in an empty workspace.

Replacement support: **“Start one edit with an existing editor: add the brief, review the version and record the final decision.”**

Keep “New project” as the first action. Do not imply an available editor marketplace just because “find your people” appears in the workflow.

## 3. Show the export allowance before setup

Current Plans & exports contains three free exports total and explains per-version consumption.

Replacement strip: **“Free includes three video-version exports total; the allowance does not reset. Downloading the same exported version again uses no new slot.”**

Test the count, failed exports and repeated downloads with owned sample files. Explain whether a failed export consumes a slot; do not guess.

## 4. Keep disabled checkout unmistakable

Current paid buttons correctly say checkout is not connected.

Replacement note: **“Paid plans are previews. Purchases are unavailable today. Use the current free allowance.”**

Keep this on the first paid-plan mention and any pricing screenshot. Do not send people to a signup page promising immediate paid capacity.

## 5. Make a note actionable

Current workflow promises feedback pinned to a frame and all versions in one place.

Replacement sample: **“Version 2 · 00:18 · replace the opening title · awaiting editor response.”** Use a fictional example, clearly labelled.

Verify exact timecode navigation, correct version association and recipient access. If frame-accurate comments are not implemented, describe the actual timestamp capability instead.

## 6. Make final approval explicit

Current tagline says “Your final say stays yours.”

Replacement confirmation: **“Approve this exact version. Check the file name and version before confirming.”**

Test whether approval is visible to both people, reversible where appropriate and distinct from metadata preparation or publishing. Do not imply automatic social upload or legal acceptance that was not verified.

Test two devices/accounts using an owned sample, unauthorized access, refresh, slow upload, file limits and actual export. Log precise failures and pause acquisition for lost/private data. A research fetch failure is not proof the public website is dead.
