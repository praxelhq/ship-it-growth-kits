# Spearn — Copy pack

Every public example uses fictional spending and explicitly illustrative card terms. Don't turn the sample catalogue into a real recommendation, application or redemption promise.

## 1. Warm invitation

> Would you inspect a sample rewards comparison and tell me which assumption is easiest to miss? I build Spearn; its current catalogue is illustrative, not live issuer data. Use made-up spending and no financial identifiers. I'd like feedback on fees, point values and simulated redemption labels, not a card application: https://spearn.sbs/app/cards.

One follow-up after seven days: “Closing the loop on the sample comparison. If it's not useful now, no problem; I won't keep nudging. If you looked, did any number seem more certain than its assumptions justified?”

## 2. Owned-feed teaching post

> A reward estimate needs its assumptions beside the total.
>
> Which spending category? What fee? What value per point? What exclusions or limits? A big number can change when one input changes.
>
> I built Spearn as a sample comparison and rewards-learning workflow. The current catalogue is illustrative, not live issuer data, and redemptions are simulated.
>
> Try fictional inputs: https://spearn.sbs/app/cards. Check the actual issuer's current terms before making a real decision. Don't spend more just to chase points.

## 3. Useful reply / clip caption

> I'd want the fee and point-value assumption next to that estimate, not only the headline reward rate. A sample calculator can explain the relationship, but current eligibility, exclusions and real redemption terms still need the issuer's documents.

Use in a relevant educational discussion. No personalized card instruction, referral link or claim that you know someone's credit situation.

Please start with made-up inputs and tell me which label needs to be clearer. It isn't a guaranteed-saving or card-approval service.
