# TaskBaddie — Measurement

## Baseline

[Public profile](https://shipped.money/p/taskbaddie), checked 29 October 2026: **0 Clarity sessions/24h** saved for 24–27 October UTC, last sync 27 October 06:15 UTC; 28 October and earlier dates include no reading, not zero. **0 settled Search clicks** for 17–23 October PT. Source active days, net revenue and PostHog have no eligible readings. No lifetime first-use/account/timer/Pro totals are known. Don't infer the app has never had users from sparse saved windows.

Keep the **1,000 B2C first-use/signup target**. Guest unique first-use sessions, optional verified accounts and installed PWAs are separate with honest deduplication limits. Don't invent signup necessity or equate four quadrants/fifty tasks with people.

## Milestones and privacy

Activation: three tasks sorted, one task chosen and a **real** focus session started. Deeper value: completed real attempt/break and voluntary later use. Landing eight-second demo completion is explicitly excluded. Session duration isn't proof of productive work or better grades; users need not disclose task contents to explain whether the session helped.

Potential aggregate events after legitimate policy/consent: first guest task, matrix sort, real timer start/pause/end, optional account sync, voluntary return, Pro recurrence success/failure. Use source/success/error/duration category only. No task words, private schedules, grades, health/attention labels, emails or music-viewing identity in analytics. Audit existing GA/Clarity masking before adding anything; don't add duplicate scripts or combine Clarity sessions with PostHog views. YouTube playback has its own data terms and shouldn't be required to start a silent session.

Private ledger: date, source visits, first-use sessions, optional accounts, real session starts/completions, timer errors, repeat use among eligible cohorts, Pro subscriptions/cancellations if legitimately known, opt-outs, hours/spend. Tags `warm-focus`, `owned-matrix`, `organizer-focus`, `peerlist`. Remove known workshop/warm overlap without fingerprinting. Cleared local storage can reset anonymous identifiers; acknowledge uncertainty.

## Weekly decisions

**Day 7:** Can five voluntary testers sort/choose and start a real session? Five is a learning gate. If only the landing animation works, fix actual app delivery rather than call the demo activation. If sorting takes too long, simplify first use instead of adding more rewards.

**Day 14:** Split timer correctness, background/sleep behavior, task persistence and account sync. If closed-tab alerts aren't implemented, don't promise them. If users expect email reminders, correct planned-only copy. Recurrence is paid; basic music/focus remain free.

**Day 21:** Compare sources on voluntary repeat session, not confetti/streak count. If the app becomes a distraction, ask what can be removed. A session started but interrupted isn't proof of laziness or a diagnosis. Separate eligible next-day/seven-day cohorts from newcomers.

**Day 28:** Review the actual accepted Day 22 exercise and return use without claiming all attendees became accounts. Check Pro recurring-task value and real billing/cancel behavior separately. PWA install isn't proof of native widget or app-store availability.

**Day 30:** Report unique first-use sessions/optional accounts separately, chosen tasks, real sessions started/completed, eligible voluntary return, errors, source overlap, hours/spend and gap to 1,000. 02 guesses only roughly 4–19 activations without the session or 9–27 with it before overlap. Unaccepted editorial/launch/directory traffic remains zero in base. No invented before/after productivity, grade or mental-health improvement.
