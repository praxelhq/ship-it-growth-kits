# Anonymous project — 30-day calendar, provisional recovery kit

**The acquisition clock starts only when identity and a usable public first action are established.** The table is a recovery-first sequence. If evidence is still missing, continue the recovery task rather than pretending a later launch happened. No generic brain-training promotion is authorized by the slug.

|Day|Main action and evidence required|Time|
|---|---|---|
|1|Reconcile the anonymous record with your own source/deployment records; #1/#2 privately.|2h|
|2|Confirm the actual product name, public URL and owner authority to publish.|2h|
|3|Open the deployment from two real network/browser routes; log the result.|2h|
|4|Write the actual user job, headline, access/price and CTA from the live page.|2h|
|5|Test the first action on a fresh phone; record success or a specific blocker.|2h|
|6|Correct the owner-controlled course entry through the usual process, #3.|1h|
|7|Checkpoint: identity and functional evidence gate. No acquisition if unresolved.|1h|
|8|Fix the first-screen explanation using only demonstrated functionality.|2h|
|9|Invite three consenting people to a fresh-user test, #4.|1h|
|10|Observe the three attempts without coaching; record actual completion.|2h|
|11|Fix the biggest common obstacle; do not rewrite the whole product blindly.|2h|
|12|Record the private evidence walkthrough A if a usable route exists.|1h|
|13|Confirm buyer/audience and provisional target with the coordinator.|1h|
|14|Checkpoint: select the real signup and activation definitions, `07`.|1h|
|15|Interview five relevant prospective users about their current alternative.|2h|
|16|Verify the actual alternative's official pricing and access terms.|1h|
|17|Find two real channels named by those users; read current rules.|1h|
|18|Request organizer/moderator permission where needed; no guessed group access.|1h|
|19|Write a specific pitch using actual evidence; replace this recovery guidance only with verified claims.|2h|
|20|Record the real first-action demo and link preview; disclose limitations.|2h|
|21|Checkpoint: usable route, three tests, audience and two checked channels.|1h|
|22|Run one small permitted invitation to the actual buyer; record the exact volume.|1h|
|23|Answer replies and repair the first conversion failure.|2h|
|24|Check whether a new user completed the real first action without you.|1h|
|25|Ask consenting testers #7 whether they voluntarily returned.|1h|
|26|Repeat the successful permitted channel only if activation occurred.|1h|
|27|Audit actual analytics and remove test/internal traffic from counts.|1h|
|28|Compare observed funnel with the retained target; show the real gap.|1h|
|29|Document what is live, limited, paid, trial-only or still unavailable.|1h|
|30|Deliver an honest recovery/growth report; unresolved identity remains unresolved.|2h|

If Day 7's gate fails, do not relabel the subsequent table as completed. Keep the next relevant task in recovery and tell the course coordinator exactly what source is missing. Hard cases deserve accurate work, not invented certainty.
