# MyWorkFolio — Measurement

## Actual baseline

[The public profile](https://shipped.money/p/myworkfolio), checked 29 October 2026, showed **0 Clarity sessions/24h** for 27 October UTC, last sync 27 October 14:22 UTC, with no reading for other displayed dates including 28 October. This isn't zero lifetime visitors or proof the app is unused. Shipping days, Search clicks, net revenue and PostHog had **no eligible readings**, not zero. Accounts, packs, private documents and paid subscribers are **not known**.

Keep the **1,000 B2C account target**, with first correct pack activation and later retrieval alongside. An illustrative quiz score, file count or multiple pack downloads isn't a new user. No need to collect real documents to establish usability.

## Definitions and data minimization

Measure aggregate signup, synthetic first-document upload/type, first pack built, ZIP successfully downloaded/checked and voluntary later retrieval. Distinguish **synthetic trial** from a user's choice to store real documents; never inspect files to classify that choice for marketing. Optional Pro subscription/payment/cancellation/refund are separate from free activation. A future-feature waitlist isn't a delivered Pro subscriber.

The privacy policy discloses Clarity anonymous website usage with signed-in vault masked, plus admin access and backup retention. Audit actual setup and consent; don't add duplicate trackers or record the vault to “see friction.” No filenames, contents, document types tied to identity, salary, ID numbers, storage links, pack ZIPs, email, phone or payment references in growth events/public logs. Use success/error/source and coarse counts only. Owner access tests use owned accounts and fake files, never other users' storage.

Private aggregate ledger: date, source, eligible adult visits, verified accounts, synthetic first pack, ZIP failure category, volunteered later retrieval, privacy objections, Pro delivery status, paid subscribers/refunds if legitimately known, opt-outs, hours/spend. Source tags `warm-career`, `owned-pack`, `organizer-career`, `peerlist`. Deduplicate known contact overlap; don't add website sessions to PostHog views or use fingerprinting.

## Weekly decisions

**Day 7:** Can five voluntary adults understand manual typing and make/check a synthetic pack? Five is a learning gate. If people expect scanning or Voice AI, correct the page. If a pack omits/mixes files, fix correctness before acquisition. No private upload is necessary for the test.

**Day 14:** Separate signup friction, upload validation, manual type, pack selection and ZIP delivery. If trust stops real storage, explain actual admin/backups/access terms; don't “solve” it by demanding sample payslips. If others' data can appear in an owned-account isolation test, stop storage outreach and repair.

**Day 21:** Look for voluntary return retrieval among eligible users, not the quiz's illustrative hours. If no one returns because no paperwork request occurred yet, distinguish not-yet-needed from failed retrieval. Don't claim a guaranteed three-hour saving or improved hiring outcomes.

**Day 28:** Review free versus delivered Pro benefits, real cancellation/refund support and privacy/deletion questions. Don't count a ₹99 early-access payment as evidence an unfinished feature worked. Cancelled Pro should retain Free documents per policy; owner verifies actual behavior.

**Day 30:** Report verified accounts, first synthetic correct packs, volunteered real-use retrieval separately, eligible return, sources after deduplication, paid subscriptions only if actually delivered, refunds, hours/spend and 1,000-account shortfall. 02 assumptions support only roughly 3–14 activations without an accepted event or 4–18 with it before overlap. No unaccepted editor/launch/directory traffic is credited. Don't publish private student names, contacts or any career-document details in a growth report.
