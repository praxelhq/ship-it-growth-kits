# FeedbackOS — Measurement

**Target:10 real businesses.** Activation beside it: **businesses independently reviewing authorized feedback and maintaining an owner/action/comparison loop in a real workspace**. The current sample demo cannot establish that activation.

## Day 0

Record actual release state, authorized live businesses, real issue histories, independently owned actions and return use from your own records. Do not use the homepage's sample 1,284 items or 58% change as a baseline. Check existing [Clarity](https://clarity.microsoft.com/) collection or configure it if absent, excluding private feedback content. Capture actual [course profile](https://shipped.money/p/feedbackos) rank, saved metric and timestamp. Unknown isn't zero. Proposed prices aren't revenue.

Events only when a real function exists: `authorized_feedback_added`, `theme_reviewed`, `owner_confirmed`, `action_updated`, `comparison_reviewed` and `business_returned`. Demo events must have a separate dataset. For actual complaint rates keep issue definition, period, numerator and denominator; a count decline isn't automatically improvement or causation.

## Four tests and release gate

The [policy](../../TARGET-POLICY.md) requires a legitimate business, its own permitted actual workflow onboarded, independent product use in the final seven days without your prompt, and a responsible person's name/callable contact held privately. Paying isn't required. A founder's manual analysis, research interview or sample-demo visit isn't a live business customer. If onboarding remains unavailable, the target isn't supported by the current release.

## Forecast and checkpoints

40 first approaches × hypothetical 25% response ×50% authorized live pilot ×50% independent reuse ≈2–3 businesses, only after the gate passes. Ten warm requests may add 0–2. **Base 2–5 is below ten; demo-only can mean zero.** These aren't observed feedback-software rates. Recompute after 20 approaches with actual release/permission evidence.
