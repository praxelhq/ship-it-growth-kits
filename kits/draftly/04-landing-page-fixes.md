# Draftly — Landing page fixes

**Provisional.** Current headline/price/CTA could not be read. On 29 October, rendered fetch failed and curl HEAD/GET returned a TLS handshake failure for the roster's `https://drafty.co.in/`. This is dated evidence, not a permanent diagnosis.

## 1. Confirm the domain, then restore trustworthy public access

Check whether the name/URL spelling difference is intentional and whether the listed canonical domain is current. Through the owner's existing host/domain controls, inspect domain attachment, HTTPS/certificate status and redirect configuration. Don't bypass a browser security warning or publish credentials. Recheck on a normal phone connection and another browser after changes.

If the URL changed, update the course link and owned links. Don't guess a similar domain that may belong to someone else.

## 2. Prove a first action before traffic

Fresh visitor → actual headline → actual CTA → one useful result. Test failure/retry, refresh and any authentication/payment boundary with owned data. If the page loads but the action doesn't, acquisition is still blocked.

## 3. Publish the factual offer

The owner must state first user/job, actual feature, price/free allowance and limits. There is no honest replacement headline to write from an empty tagline. A temporary status page can say: **“Draftly's public access is being restored. No new offer is being promoted here until the first-use flow is verified.”** Don't claim every service is stopped if only public access is uncertain.

## 4. Add proof from the recovered flow

Use one owned/synthetic input and an actual output. Label examples, don't invent testimonials or statistics. Any price or turnaround claim must match the real product.

## 5. Check privacy and phone behaviour

Publish the real data-processing/support/deletion information before collecting input. Check 390px layout, keyboard, slow network, long text and CTA destination. A loaded desktop screenshot isn't mobile verification.

## 6. Repair the shared-link trail

Once the actual offer is known, make title/description/image match it and remove stale or wrong-domain links. Until then, use a status preview, not a made-up feature claim. No personal data or access-bearing links in the image.
