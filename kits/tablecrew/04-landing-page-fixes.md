# Tablecrew — Landing page fixes

**Provisional. Current headline, price and CTA: unavailable to verify.** On 29 October, rendered fetch rejected the listed URL and both HEAD and GET failed DNS resolution for www.tablecrew.live. The roster independently records the site as down; other cohort sites were reachable. These dated observations do not prove permanent worldwide downtime. The empty tagline does not establish restaurant software, table booking or social dining.

## 1. Resolve the actual destination

Ask the owner to confirm the exact canonical URL, including whether www is intentional. Review ownership, domain attachment and DNS using the actual provider’s controls. Do not send testers to a guessed apex or similar domain. Then verify HTTPS and one real first-use action from another connection.

## 2. Prove a first action before traffic

Fresh visitor → actual headline → actual CTA → one useful result. Test failure/retry, refresh and any authentication/payment boundary with owned data. If the page loads but the action doesn't, acquisition is still blocked.

## 3. Publish the factual offer

The owner must state first user/job, actual feature, price/free allowance and limits. There is no honest replacement headline to write from an empty tagline. A temporary status page can say: **“Tablecrew’s listed public address is being checked. We will publish a confirmed link and actual offer before inviting new users.”** Don't claim every service is stopped if only public access is uncertain.

## 4. Add proof from the recovered flow

Use one owned/synthetic input and an actual output. Label examples, don't invent testimonials or statistics. Any price or turnaround claim must match the real product.

## 5. Check privacy and phone behaviour

Publish the real data-processing/support/deletion information before collecting input. Check 390px layout, keyboard, slow network, long text and CTA destination. A loaded desktop screenshot isn't mobile verification.

## 6. Repair the shared-link trail

Once the actual offer is known, make title/description/image match it and remove stale or wrong-domain links. Until then, use a status preview, not a made-up feature claim. No personal data or access-bearing links in the image.
