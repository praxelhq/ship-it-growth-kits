# NudgeBooks — Phone-demo scripts

Use a fictional practice/client and invented document labels, with no real financial files or contact data. Record your screen and voice. Only show a request/status/reminder action as operational after verifying it; never send a real follow-up during recording without separate permission.

## A. Before the next nudge — 65 seconds

0–3 s: fictional monthly document list. **“What is still missing?”**

3–16 s: actual entry and supported cycle setup. “Start with one recurring collection, not the whole practice.”

16–32 s: actual request/receipt route using synthetic records. “Show what was asked for and what actually arrived.” If unsupported, stop at the actual boundary and label the missing feature.

32–47 s: real outstanding-state review. “A sent message is not a received document. Check the period and intended item.” Leave one supported interaction uncut.

47–55 s: permission/next-action review. “The owner decides what follow-up is appropriate.” No fake automatic WhatsApp message.

55–65 s: actual entry and offer state. “Inspect the current workflow and terms before client data. nudgebooks.in.”

## B. Period hook — 20 seconds, Short

0–3 s: synthetic file labels for two different months. **“A file arrived. Is it the right one?”**

3–12 s: actual supported receipt/status check, or a labelled owner checklist. “Confirm the intended item and period before clearing it from outstanding.”

12–20 s: current product boundary and URL. “A clearer next follow-up starts with a clearer list.”

## C. Automation boundary — 25 seconds, LinkedIn

0–3 s: metadata promise beside the actual public sign-in. **“Less chasing needs a real workflow.”**

3–15 s: verified supported steps; mark any unavailable capability explicitly. “Do not call a reminder automatic until the actual route and permission work.”

15–25 s: synthetic example and current terms. “Start with the evidence, then choose whether to use real data.”

Capture actual entry, real supported cycle fields, receipt/outstanding distinction, access/storage limits and current offer when established. If only authentication is available, use the public-boundary explainer and repair the product before recording a success demo. Label shortened waits; no invented CA testimonials.
