# Media Chronicle — Measurement

## Baseline and release condition

On 29 October 2026, [the public profile](https://shipped.money/p/media-chronicle) showed **no eligible readings** for authored-source active days, Clarity sessions, Search clicks, net revenue and PostHog. It also displayed 5,280 authored lines/one merged PR in seven days; these aren't users or product quality evidence. Traffic, installs, buyers and retention are **not known**, not zero.

The actual linked trial destination currently has no releases. Record this as a failed delivery route, not a dead website or inferred zero customers. A published installer/version, normal download/install and small-library first scan/search are the release gate. Until passed, count website interest separately and forecast **zero usable trial activations**.

## Milestones and target

Keep the **1,000 B2C install/license target**; split trial first launches, individual paid buyers, licenses and installed PCs. A three-PC license doesn't equal three customers. Activation is a successful small sample index plus a retrieved known photo/source drive. Deeper value is disconnected preview comprehension and later voluntary retrieval. A scan of 10,000 files isn't 10,000 users.

Possible aggregate events, only if actual privacy/consent allows: website `trial_clicked`, `checkout_started`, owner-confirmed `license_delivered`; opt-in usability counts for install/index/search/reconnect. The desktop says no telemetry: don't contradict that by silently adding growth tracking. If no consented app instrumentation exists, use volunteered aggregate test observations and unknown totals rather than inventing a measurement stream.

No images, face embeddings, EXIF coordinates, names, filenames, drive labels, directory paths, license keys or hardware identity in growth analytics/replays. Website/payment records differ from local-photo indexing. Audit existing trackers and actual policy before installing another one. Source links distinguish `warm-archive`, `owned-release`, `organizer-archive`, `peerlist`; remove legitimate known overlap without fingerprinting.

## Private aggregate log

Date, readiness gate, actual invitations/posts, source visits, successful known trial launches, first index/search, disconnected preview understood, original access after reconnect, crashes/corrupt files, paid licenses, refund requests, hours, spend. Record sample size/formats/PC specs with owner's permission and no private media. Keep performance measurements tied to the actual test build/sample, not general promises.

## Weekly checkpoints

**Day 7:** Is the trial actually downloadable/installable? Can five voluntary supported-PC tests find a known sample photo without altering originals? Five is a learning gate. If delivery is missing, fix it; don't optimize a checkout headline or celebrate trial clicks as installs.

**Day 14:** Split install, indexing, query and drive-reconnection failures. If users think a preview is a backup, change 04 copy immediately. If scans are slow, measure hardware/sample formats before promising 100,000-photo performance. Never delete originals or backups for an experiment.

**Day 21:** Look for voluntary second retrieval, not merely an index completed while waiting. If full-resolution access fails when disconnected, explain the intended source requirement versus a real bug. Resolve license/update terms before interpreting willingness to pay. A refund-policy page isn't proof of tested refund fulfillment.

**Day 28:** Compare source cohorts on working first catalogue/search and support burden, with paid conversion separately. If the release remained unavailable, report the month as readiness work with actual zero observed trials, not a growth success. Unknown lifetime users remain unknown.

**Day 30:** Report release state, actual invitation volume, visits, known trial launches/activation, repeated retrieval, paid buyers/licenses/PCs separately, refunds, hours/spend and target shortfall. With all readiness gates and invitations fulfilled, 02 guesses only roughly 3–13 activations without a session or 4–16 with it before overlap. If not, reduce the forecast to the actual inputs; unaccepted launches/editorial/directories contribute zero. No claim of universal offline privacy, perfect search or cloud-backup savings without appropriate evidence.
