# Roomly — 30-day calendar

**Preflight:** confirm canonical public destination, resolve HTTPS access, obtain the factual product brief and prove one first-use result. Until those pass, stay on recovery and do not start the acquisition clock. Day 1 below begins when the real product is inspectable.

| Day | Main job | Time |
| --- | --- | --- |
| 1 | Record real baseline and fresh-browser first-use test. | 3h |
| 2 | Write positioning from actual user/job, headline, CTA and price. | 2h |
| 3 | Repair the first conversion or privacy issue. | 3h |
| 4 | Record verified demo A with owned/synthetic data. | 2h |
| 5 | Invite five willing users matching the verified job (#3). | 1h |
| 6 | Observe actual first-use completion, not just page opinion. | 2h |
| 7 | Checkpoint: working access, real trials, useful result. | 1h |
| 8 | Correct the biggest confusing offer/action sentence. | 2h |
| 9 | Verify the actual buyer's primary channel and rules. | 2h |
| 10 | Invite five more matching testers after fixes. | 1h |
| 11 | Publish one truthful owned update using recovered facts. | 1h |
| 12 | Support first users; no paid distribution. | 2h |
| 13 | Record actual limit explainer D. | 1h |
| 14 | Checkpoint: observed rate replaces guesses. | 1h |
| 15 | Fix the most important first-use failure. | 3h |
| 16 | Ask one real relevant group admin for permission, not a generic list. | 30m |
| 17 | Share only the approved factual invitation if accepted. | 1h |
| 18 | Improve return/recovery path. | 2h |
| 19 | Record a second real use-case lesson without invented proof. | 1h |
| 20 | Publish on the owned channel with actual useful users. | 1h |
| 21 | Checkpoint: repeat use and persistent access. | 1h |
| 22 | Optional Peerlist if usable/current rules permit; otherwise skip. | 1h |
| 23 | Fix one actual issue from feedback. | 2h |
| 24 | Review every URL/price claim again. | 1h |
| 25 | Repeat the best relevant route, not unverified communities. | 2h |
| 26 | Ask willing testers about return/usefulness. | 1h |
| 27 | One follow-up only to people who welcomed contact. | 30m |
| 28 | Checkpoint: unique people versus tests/retries. | 1h |
| 29 | Write the next month's channel arithmetic from observed data. | 2h |
| 30 | Report actual users/activation, access status and target gap. | 2h |

If access fails again, pause new traffic and fix it. The calendar doesn't authorize inventing a feature or community to keep moving.
