# Postifyy — 30-day calendar

Day 1 starts when you can work on the product. Public promotion starts only after the Day 2 conversion gate passes. Times below are chosen for a student in India, not claimed algorithmic best times. Reply to genuine comments for 30 minutes daily and log accounts plus approved drafts each evening.

Keep your primary campus invitation window on Days 17–20. If the cohort's actual start dates differ, coordinate the calendar with organizers rather than treating relative day numbers as protection from overlap.

| Day | Main action | Time / output |
| --- | --- | --- |
| 1 | Record the `07` baseline. Check existing Clarity before adding a second tag; mask draft bodies and sign-in data. Read the current free limits and checkout wording. | 2h; baseline and event definitions. |
| 2 | Watch three students test mobile sign-in → real story → edited draft → export/approval. Apply `04` Fix 2. If the essential flow fails, pause the calendar's promotional actions until repaired. | 3h; observed funnel, not guesses. |
| 3 | Build the focused student path and clear free-limit copy (`04` Fixes 1 and 4). Keep the game secondary. | 3h; one conversion path. |
| 4 | Record Video A from a real project. Save the original explanation and corrected draft. | 2h; 60-second proof. |
| 5 | Publish `03` #4 at 09:00 IST on your own LinkedIn. Answer every substantive reply for the next hour. | 2h; first measured post. |
| 6 | Talk privately to five classmates who clicked but did not make a draft. Ask where they stopped; do not write a second launch post. | 1.5h; friction list. |
| 7 | Week 1 checkpoint in `07`. Compare accounts with approved/exported drafts. Fix the single largest observed drop-off. | 2h; one prioritized repair. |
| 8 | Build Video C, using your own factual edit. Publish its checklist as useful owned content, `03` #8. | 2h; first teaching asset. |
| 9 | Prepare a list of ten relevant campus organizers through existing relationships. Ask for introductions, not student contact exports. Check the shared organizer calendar. | 1.5h; private qualified list. |
| 10 | Improve the existing student post-ideas guide with one actual demonstration and the public demo link. | 2h; resource, not a new side product. |
| 11 | Publish a second LinkedIn demonstration with a different real project decision. Record clicks separately from the first post. | 1.5h; repeatable angle test. |
| 12 | Prepare Peerlist copy #6, screenshots and the working demo. Inspect the current launch slot and rules; do not announce an unavailable Monday. | 2h; ready listing. |
| 13 | Run a small rehearsal with five willing classmates. Use `03` #3. Let them export without forcing public posts. | 2h; clinic timing and completion count. |
| 14 | Week 2 checkpoint. If fewer than half the rehearsal participants finish a draft, fix the exercise before inviting more groups. | 2h; go/no-go for clinic scale. |
| 15 | Build the lightweight share request after successful export, copy #5. Keep it optional and track clicks without exposing names. | 2h; referral test. |
| 16 | Publish Video B. Confirm who owns each invitation in the shared organizer calendar. | 1.5h; clear schedule. |
| 17 | Send up to five personal organizer invitations, copy #1. Ask to show the exercise before requesting a group announcement. | 2h; permission requests. |
| 18 | Hold an accepted clinic, or do five one-to-one tests if no organizer accepted. Organizer sends copy #2 only after permission. | 2.5h; real attendee/account/draft counts. |
| 19 | A second accepted clinic or useful follow-up with actual attendees. Ask why any draft was rejected. | 2.5h; edited examples and objections. |
| 20 | Third clinic if booked; otherwise help the first group finish. Ask one satisfied organizer for a direct introduction to another campus. | 2h; introductions, not assumed partnerships. |
| 21 | Week 3 checkpoint. Calculate the remaining visitors needed for 1,000. If the partner network is not expanding, report the gap and choose the highest-activation channel. | 2h; honest forecast. |
| 22 | Launch on the next available eligible Peerlist Monday, or publish the project entry and wait for that slot. Use copy #6; adjust other tasks around the actual date. | 2h; accurate listing. |
| 23 | Review five long landing-page sessions that did not lead to sign-in. Change only the most common confusing sentence. | 2h; evidence-based copy change. |
| 24 | Follow up once with organizers contacted on Day 17. Stop after a decline or silence after this follow-up. | 1h; no repeated pressure. |
| 25 | Publish a permissioned before/after from a real participant, or another example from your own project if permission is absent. | 2h; proof without fabricated praise. |
| 26 | Record Video D to explain the plan limits. Decide whether Product Hunt is worth a later launch; no paid hunter, no duplicate listing. | 1.5h; answer the actual pricing objection. |
| 27 | Run the fourth clinic only if accepted. Otherwise repeat the one-to-one path that produced the most completed drafts. | 2h; activation first. |
| 28 | Week 4 checkpoint. Ask ten early users whether they made another post in the last seven days. Do not count your reminder as independent return usage. | 2h; retention evidence. |
| 29 | Give the best channel one focused repeat: new project, new edit, same useful exercise. Drop channels with no qualified visits after two real attempts. | 2h; deliberate repeat. |
| 30 | Reconcile unique accounts, activated writers, repeat writers, payments and refunds. Write the month report in `07`; set next month's plan from measured results. | 2h; truthful handoff. |

If a genuine post attracts a sudden wave, postpone the next publication and spend the day helping those people finish their first draft. An inbox full of unanswered questions is not a reason to launch on another platform.
