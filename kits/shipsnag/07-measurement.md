# ShipSnag — Measurement

**Target: 1,000 distinct individual skill installs/first runs**, the policy-equivalent consumer signup count for a no-product-account download. Report **one meaningful proof report reviewed against actual project checks** alongside. ZIP clicks/downloads aren't successful installs; an install without a first usable run isn't activation. Repeat runs, multiple skills per person, paid purchases and newsletter interest are separate.

## Day 0

Record actual free downloads, voluntarily confirmed successful installs/runs, report correctness, independent return runs and real purchase/refund records. No private baseline was established here. Capture current [course profile](https://shipped.money/p/shipsnag) rank, saved reading, period and timestamp. Operator benchmark cases and example reports aren't customer outcomes.

The product says scripts make no network/telemetry calls and its optional local ledger is written only with approval. Preserve that boundary. Do not add hidden telemetry to skills to improve a growth dashboard. Check the website's existing [Clarity](https://clarity.microsoft.com/) and consent before adding tracking; mask emails and never record pasted secrets/repo content. Native first-run/use may need a voluntary test log rather than automatically available analytics. State uncertainty in install estimates and deduplicate conservatively.

Useful aggregate steps, only where legitimately measurable: skill-page viewed → ZIP downloaded → install voluntarily confirmed → supported proof run → actual report reviewed → independent later run. Classify failures as folder/agent discovery, Python/tool dependency, unsupported command, timeout, skipped check, false finding or misleading verdict. Don't log full paths containing private identifiers, code or secret values in public reports.

## Calendar arithmetic

Assumed rates, not measured developer channels:

- 40 invitations × 50% try × 70% successful install/run = **14 installs**.
- Six posts × 300–1,000 impressions × 2% visits × 15% install ≈ **5–18 installs**.
- One optional Show HN × 0–300 visits × 10% install = **0–30**.
- One optional Peerlist × 0–150 visits × 10% install = **0–15**.

Total **19–77 before overlap**, below 1,000. Owned guide updates and existing Product Hunt activity add zero guaranteed traffic. At an assumed 15% qualified-visitor-to-install rate, the target needs about 6,667 qualified visitors, far more than the scheduled small experiment. Verify real install conversion before expecting any launch to fill the gap.

| Checkpoint | Working milestone | Diagnose if behind |
| --- | --- | --- |
| Day 7 | Five installs/runs, three reviewed reports | Fix package/guide/agent discovery before broader posts. |
| Day 14 | Ten installs, seven reviewed reports, three independent returns | Separate install success from report usefulness; inspect NOT VERIFIED confusion. |
| Day 21 | Twenty installs or actual count, repeat runs and incorrect verdicts recorded | Improve evidence/coverage and current-agent scope, not benchmark hype. |
| Day 28 | Thirty installs or actual count; final-week independent use | Deduplicate downloads, reinstalls and multiple skills per person. |
| Day 30 | Actual progress toward 1,000 with reviewed proofs beside it | Report target gap, true source conversion, purchases/refunds and support time. |

Review ten controlled proof cases with known expected outcomes, including missing checks and deliberately seeded failures. Small convenience tests don't establish universal security or accuracy. A report may correctly say it can't verify production; count that as an honest boundary, never as a proven avoided outage or prevented bill.
