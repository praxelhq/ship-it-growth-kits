# Ledgerly — Video scripts

Three deliberately fictional messages, no real bank identifiers, balances, OTPs, card numbers, statements or client records. Label every amount Sample. Record actual parsing/review behaviour with phone voice and screen capture.

## A · Three messages, a checked khata · 60 seconds · own feed / listing

| Time | Shot / text | Say |
| --- | --- | --- |
| 0–2s | Fictional debit messages. **“Does the total match?”** | “A neat khata still needs checking.” |
| 2–14s | Actual supported input and data notice. | “I'm using made-up messages, not a bank connection.” |
| 14–29s | Real parsed result beside source. | “I check the amount, date and category.” |
| 29–43s | Actual duplicate/uncertain state or correction. | “This entry needs review. A guess shouldn't silently become a fact.” |
| 43–53s | Real reviewed total and review list. | “A recurring flag is a question to inspect, not a cancellation.” |
| 53–60s | Current access/URL. | “Start with a synthetic example at Ledgerly dot page.” |

If parsing fails, show and repair it; don't type a perfect result over a failed import. Only demonstrate PDF/CSV if the actual format passed your test.

## B · Potential versus kept · 20 seconds · short lesson

Hook: **“This isn't money saved yet.”** 0–8s, show a clearly fictional potential amount. 8–15s: “The household still decides, the provider must actually stop billing and a later charge needs checking.” 15–20s: “Keep estimates and outcomes separate.” No specific cancellation instruction or promised rupees.

## C · Same message twice · 25 seconds · review help

Hook: **“Two imports don't mean two purchases.”** 0–8s, synthetic duplicate pair. 8–18s, show actual review/deduplication if supported: “I compare source/date/amount before trusting the total.” 18–25s: “Uncertain records need a visible check.” If no duplicate feature exists, demonstrate manual review honestly instead of inventing one.

## D · No bank login · 20 seconds · trust explanation

Hook: **“The test doesn't need your bank password.”** 0–8s, show synthetic input and actual sign-in explanation. 8–15s: “Ledgerly uses an email link for its account. Read the record-processing terms separately.” 15–20s: “Never send OTPs or account/card details for feedback.” Don't imply email login establishes all privacy controls.
