# Lawyer OS — Measurement

**Target: 10 real business customers in 30 days.** Count genuine independent/firm practices under [all four policy tests](../../TARGET-POLICY.md): real operation; own actual authorized matter data onboarded; independent use in the last seven days; privately known owner name and phone. Keep identifying details outside the public repo. Free-active practices can count; sample-only evaluators cannot.

Activation: the advocate reviews its own permitted matter overview and verifies the next date/status against its existing record. Report this beside business totals. A synthetic demo does not activate a real practice; clients, cases and lawyers inside a firm do not multiply customer businesses. No deadline-prevention or legal-outcome metric is inferred.

Private records were not accessed; baseline totals are unknown.

| Baseline | Source / boundary |
| --- | --- |
| Genuine practices / latest independent use | Workspace records plus private permitted owner register; exclude tests/assisted-only sessions. |
| Own authorized records onboarded | Owner-confirmed actual business data, minimally identifying where possible. |
| Reviewed next-date/status records | Status metadata and consented owner feedback, not case facts in growth analytics. |
| Role/file/recovery errors | Synthetic reproductions and private issue categories. |
| Actual plan/payment/refund | Billing records; sample quote values and seat counts are not revenue/customers. |
| Traffic/course baseline | Existing consented analytics and [profile](https://shipped.money/p/lawyeros), timestamp/period. |

Check existing [Clarity](https://clarity.microsoft.com/) before adding a duplicate. Exclude case/client names, dates where identifying, documents, legal notes, file links, account/payment fields and acceptance details from replay. Aggregate events can record owncasecreated, overviewreviewed, dateverified, returnuse, exportcompleted only if supported. Do not copy case files into a growth dashboard.

| Checkpoint | Decision |
| --- | --- |
| Day 7 | Eight approaches scheduled. If safe actual-data permission or access cannot be established, remain at sample evaluation and report the gate. |
| Day 14 | 20 approaches. Compare real owned onboarding and review against sample-only interest. Do not count a student or colleague testing a fictional matter. |
| Day 21 | 28 approaches. Inspect independent recent use and actual record clarity; keep existing deadline controls. |
| Day 28 | 40 approaches. Audit all four tests and count practices rather than seats. |
| Day 30 | Report actual qualifying practices against ten, activation, recent use, real payments, hours and unresolved gaps. |

Base guesses: 40 × 50% × 70% × 70% = 9.8 businesses; at 25% conversation, 4.9. Three posts and two introductions are upside only. Replace rates after eight approaches and again after 20. Permission barriers may reduce onboarding below this model; show the real gap instead of asking for sensitive data without authorization.

A recorded hearing date is not a verified court update, a generated file is not a legal result and a sample demo is not a security audit. Publish only permitted aggregate workflow observations. Do not claim fewer missed hearings, successful cases or professional compliance without real, appropriately reviewed evidence.
